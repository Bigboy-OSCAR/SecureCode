# UI Rule 명세서

## 1. 문서 목적

본 문서는 LocalDesk 로컬 LLM 워크스페이스 UI 프로토타입을 기준으로, 화면 객체가 따라야 하는 UI 규칙을 정의한다. 이 문서는 UI 객체의 동작 규칙을 다음 세 가지 관점으로 분리하여 정의한다.

1. **Constant Behaviour**: 현재 상태와 무관하게 항상 같은 방식으로 동작하는 UI 객체의 규칙
2. **Varying Behaviour**: 선택 프로젝트, 폴더 선택 여부, 대화 유무, 모델 선택·로딩 상태, 인덱스 대상 및 작업 상태에 따라 다르게 동작하는 UI 객체의 규칙
3. **Entry & Exit Rule**: 화면 또는 팝업에 진입할 때 수행되는 규칙과, 화면 또는 팝업을 벗어날 때 수행되는 규칙

본 문서에서 말하는 “화면”은 전체 페이지 단위의 UI를 의미하고, “팝업”은 현재 화면 위에 표시되는 모달 또는 플로팅 패널을 의미한다.

작성 형식은 [원본 UI_Rule.md](/Users/oscar/Desktop/Binance_Auto/Design/UI/UI_Rule.md)의 장 순서, CR·VR·ER 구분, 규칙별 표 구조, 흐름 요약, 검증 체크리스트, Rule ID 목록을 따른다. 동작 근거는 [LocalDesk Figma 프로젝트](https://www.figma.com/design/oDegAXjc7iIY8yb138uHG1/LocalDesk?node-id=0-1)의 화면·문구·컴포넌트 설명·프로토타입 연결이며, 확인일은 2026-10-28이다.

## 3. UI Rule 작성 기준

각 규칙은 다음 정보를 기준으로 정의한다.

| 항목 | 의미 |
|---|---|
| Rule ID | 규칙 식별자이다. Constant Behaviour는 `CR`, Varying Behaviour는 `VR`, Entry & Exit Rule은 `ER` 접두사를 사용한다. |
| 대상 UI 객체 | 규칙이 적용되는 버튼, 입력 영역, 체크박스, 팝업, 화면 영역이다. |
| 사용자 이벤트 | 사용자가 발생시키는 클릭, 입력, 선택, 키 입력, 화면 진입, 화면 이탈 이벤트이다. |
| 선행 조건 | 해당 규칙이 적용되기 위해 필요한 현재 상태이다. Constant Behaviour에서는 보통 `항상`으로 작성한다. |
| 시스템 반응 | 이벤트 발생 후 UI가 수행하는 Action 또는 화면과 문구로 확인되는 역할이다. |
| 상태 변경 | 선택 프로젝트·대화·모델, 폴더 입력, 검색어, 인덱스 선택값·진행 상태, 팝업 표시 상태 등의 변경이다. |
| 시각적 피드백 | 버튼 강조, 체크 상태, 진행률, 팝업 표시, 대화 내용 변경 등 사용자가 확인할 수 있는 변화이다. |

각 규칙 아래의 **[연결 확인]**은 Figma에 실제 이벤트·목적지 연결이 있음을, **[화면·문구 확인]** 또는 **[컴포넌트 설명 확인]**은 화면이나 설명에 역할이 명시되어 있음을 의미한다. **[정의 필요]**는 클릭 연결·처리 결과·상태 보존 정책 등이 확인되지 않았음을 의미한다. 미연결 객체도 누락하지 않고 역할과 미확인 범위를 함께 기록한다.

버튼과 카드의 레이어 이름에 `→ main`, `→ history`, `→ error`가 있어도 액션이 없으면 연결된 동작으로 간주하지 않는다. 하위 아이콘·배지가 부모 행의 클릭 영역에 포함된 경우에는 독립 버튼으로 중복 정의하지 않는다. 숨겨진 객체와 모달 뒤에 가려진 배경 객체의 연결은 사용 가능한 전면 버튼과 구분한다.

폴더 선택·검색·LLM 응답은 안내 화면에서 예시 데이터라고 명시되어 있다. 연결된 화면 이동은 실제 파일 접근·프로젝트 저장·모델 실행·클립보드 복사·인덱싱 성공의 증거가 아니다. 모델·날짜·진행률·경로·개수는 예시값과 동적 정책을 구분한다.

Figma의 팝업들은 대부분 전체 화면 프레임 간 `NAVIGATE`로 표현되어 있다. 이 때문에 고정된 `01` 화면으로 돌아가는 동작이 있으며, 실제 앱의 이전 상태 복원으로 일반화하지 않는다. `BACK` 연결은 직전 프로토타입 화면으로 복귀하는 동작이다.

# 4. Constant Behaviour

Constant Behaviour는 선택 프로젝트, 모델 선택·로딩 여부, 폴더 선택 여부, 인덱스 작업 상태와 별개로 각 UI 객체가 맡는 기본 반응과 역할을 정의한다. 같은 객체의 상태별 차이는 Varying Behaviour에서 별도로 정의한다.

---

## CR-01. 상단 및 로컬 상태 표시 규칙

| 항목 | 내용 |
|---|---|
| 대상 UI 객체 | `LocalDesk`, `LOCAL`, 프로젝트명·경로, 대화 제목, `이 기기에서만 실행·저장`, 하단 저장 안내 |
| 사용자 이벤트 | 없음 |
| 선행 조건 | 해당 워크스페이스 화면이 표시된 상태 |
| 시스템 반응 | 현재 화면의 프로젝트·대화 맥락과 로컬 실행·저장 안내를 표시한다. |
| 상태 변경 | 없음 |
| 시각적 피드백 | 선택한 프로젝트 카드, 상단 제목, 입력창의 프로젝트 이름을 표시한다. |

[화면·문구 확인] 로컬 저장 안내, 모델 수 `3`, 프로젝트 옆 `4`, 날짜, `응답 완료`는 정보 표시이다. 별도의 클릭 기능은 확인되지 않는다. 이름·개수·날짜·경로는 프로토타입 예시이며 실제 제품의 고정값으로 사용하지 않는다. 모델 실행 상태의 분기는 VR-05에서 정의한다.

## CR-02. 윈도우 및 패널 아이콘 규칙

| 항목 | 내용 |
|---|---|
| 대상 UI 객체 | 타이틀바의 빨강·노랑·초록 원형 컨트롤, 타이틀바 우측 패널 아이콘 |
| 사용자 이벤트 | 각 컨트롤 클릭 |
| 선행 조건 | 워크스페이스가 표시된 상태 |
| 시스템 반응 | 창 제어 및 패널 보기 조작을 연상시키는 외형을 표시한다. 현재 프로토타입에는 실행 연결이 없다. |
| 상태 변경 | 창 종료·최소화·확대 또는 패널 표시 상태 변경은 미확인이다. |
| 시각적 피드백 | 타이틀바에 원형 컨트롤 3개와 패널 아이콘을 표시한다. |

[정의 필요] 실제 창 닫기·최소화·전체화면 지원 여부, 우측 아이콘이 여는 패널의 종류, 앱 종료 시 진행 작업 처리 정책은 정의되어 있지 않다. OS 동작을 프로토타입의 확인된 기능으로 간주하지 않는다.

# 5. Varying Behaviour

Varying Behaviour는 같은 UI 객체라도 현재 시스템 상태나 입력값에 따라 다른 결과를 내는 규칙이다. 이 영역에서는 반드시 조건과 분기 결과를 함께 정의한다.

## VR-01. 프로젝트 선택 상태 분기 규칙

| 현재 상태 | 사용자 이벤트 | 시스템 반응 | 상태 변경 | 시각적 피드백 |
|---|---|---|---|---|
| SecureCode 대화 화면 | 다른 프로젝트 `Research Notes` 클릭 | `06 · 프로젝트 시작`으로 이동한다. | 표시 프로젝트가 Research Notes로 변경된다. | Research Notes 경로, 새 대화, 빈 대화 안내를 표시한다. |
| Research Notes의 시작·모델 미선택 화면 | 다른 프로젝트 `SecureCode` 클릭 | `01 · 메인 대화`로 이동한다. | 표시 프로젝트가 SecureCode로 변경된다. | 기존 예시 대화와 SecureCode 경로를 표시한다. |
| 현재 선택된 프로젝트 카드 | 카드 본문 또는 접기 화살표 클릭 | 별도 연결이 없다. | 변경 결과 미확인 | 현재 선택 표시를 유지한다. |
| 프로젝트별 미전송 입력 또는 실행 작업 존재 | 다른 프로젝트로 이동 | 초안·모델·인덱스 작업의 승계 또는 분리 정책은 정의 필요이다. | 정의 필요 | 전환 후 프로젝트별 상태 복원 화면은 없다. |

[연결 확인 / 정의 필요] 프로젝트 행의 연결은 화면 예시 간 이동이다. 다른 프로젝트를 선택했다고 실제 프로젝트를 새로 생성하는 것으로 해석하지 않는다.

| `03`·`04`·`05`·`07`·`11`·`12` | Esc | `01`로 이동한다. | 팝업 이탈 | 메인 예시 표시 |
| `16`·`17` | Esc | `BACK`을 실행한다. | 직전 화면 복귀 | 직전 화면 표시 |
| `08`·`18`·`19` | Esc | Esc 연결이 없다. | 정의된 종료 결과 없음 | 현재 표시 유지 |
| 검색 진입 안내 `⌘ K` | Command+K | 키 입력 연결이 없다. | 검색 팝업 진입 미확인 | 단축키 안내만 표시 |
| 작성창 안내 `Enter로 전송` | Enter 또는 줄바꿈 조합 | Enter 연결과 Shift+Enter 정책이 없다. | 실제 입력·전송 결과 미확인 | 안내 텍스트 표시 |
| `03` 프로젝트 만들기 | 비활성 모양 버튼 클릭 | 액션이 없다. | 전환 없음 | 비활성 외관 유지 |
| `14` 전송 버튼 | 비활성처럼 보이는 버튼 클릭 | `07`로 이동한다. | 모델 선택 팝업 표시 | 모델 선택 유도 |

[연결 확인 / 정의 필요] 버튼 외관·실제 액션·키보드 접근을 독립적으로 검증한다. 마우스로 연결된 동작이 있다고 해서 키보드 조작도 지원된다고 기술하지 않는다.

# 6. Entry & Exit Rule

Entry & Exit Rule은 화면이나 팝업에 진입하는 순간 자동으로 수행되어야 하는 규칙과, 화면이나 팝업을 벗어날 때 수행되어야 하는 규칙이다. 버튼 클릭 자체의 기능 설명이 아니라, 화면 생명주기 관점의 규칙이다.

---

## ER-01. 메인 대화 화면 Entry Rule

| 항목 | 내용 |
|---|---|
| 진입 대상 | `01 · 메인 대화` (`3:476`) |
| 진입 이벤트 | 안내 화면의 메인 시작, 연결된 메인 복귀·대화 행·전송 등 |
| Entry Rule | SecureCode 프로젝트, 선택된 `프로젝트 구조 살펴보기` 대화, Qwen 7B 실행 상태를 표시한다. 예시 질문·응답, 폴더 카드, 코드 블록과 작성창을 표시한다. |
| 기본 표시 상태 | 프로젝트 사이드바·대화·모델 선택 영역·입력창이 함께 표시된다. |

[화면·연결 확인] 프로토타입 시작점으로 지정되어 있다. 실제 앱 최초 실행 시 프로젝트·모델을 자동 복원하는 정책은 정의 필요이다.

# 8. UI Rule 검증 체크리스트

| 체크 항목 | 검증 내용 |
|---|---|
| Constant Behaviour 분리 여부 | 기본 역할·대상·이벤트·반응·상태·피드백이 CR 표로 정의되어 있는가? |
| Varying Behaviour 분리 여부 | 프로젝트·폴더·모델·대화·인덱스 상태에 따른 차이가 조건별로 정의되어 있는가? |
| Entry Rule 정의 여부 | 모든 화면·팝업의 진입 이벤트와 초기 표시가 정의되어 있는가? 실제 조회 정책이 없는 부분을 구분했는가? |
| Exit Rule 정의 여부 | 취소·닫기·확정·시간 경과별 이탈 경로와 유지/미확인 상태가 구분되어 있는가? |
| 조사 범위 | 프로토타입 화면 18개와 UI 컴포넌트 9개를 모두 포함했는가? 현재 없는 `02`·`10` 화면을 추정해서 추가하지 않았는가? |
| 버튼 외 객체 | 텍스트 입력, 체크박스, 링크, 클릭 가능한 행, 아이콘, 정보 배지를 함께 점검했는가? |
| 프로젝트 추가 경로 | 제목 옆 `+`와 `+ 프로젝트 추가`가 같은 새 프로젝트 팝업으로 연결되는가? 첨부 `+`와 구분했는가? |
| 폴더 선택 전후 | 미선택 상태의 만들기는 비활성 모양·미연결이고 선택 후 만들기는 시작 화면으로 연결되는가? |
| 폴더 취소 예외 | 폴더 팝업의 취소는 `03`, 닫기·배경·Esc는 `01`로 이동한다는 차이를 기록했는가? |
| 프로젝트 이름 | 자동 입력·수정 가능 안내와 실제 타이핑·검증 기능의 미구현을 구분했는가? |
| 새 대화 아이콘 | 작성 아이콘은 미연결이며 `15`로 가는 액션이 없다는 점을 기록했는가? |
| 대화/이전 대화 연결 | 포인터·README 행, 이전 대화 버튼, 패널 아이콘과 안내 카드의 미연결을 누락하지 않았는가? |
| 모델 변경 시 대화 보존 | 변경 후 상단 모델은 Llama지만 기존 응답 작성자는 Qwen이며 다음 응답부터 적용한다는 문구를 반영했는가? |
| 모델 미선택 전송 | 어두운 전송 버튼에도 `07` 이동 연결이 있다는 외관·동작 차이를 기록했는가? |
| 모델 로딩 취소 | 보이는 취소 버튼은 미연결, `×`는 숨김, 배경은 메인 연결, Esc는 미연결임을 구분했는가? |
| 로딩 예시값 | 68%와 약 1.6초 자동 전환을 실제 로딩 보장·성공 판정으로 기술하지 않았는가? |
| 모델 관리 및 메모리 | 설치 목록·저장 위치 표시, 32B 메모리 확인 미연결, 오류 화면 부재를 기록했는가? |
| 검색 결과 불일치 | 이전 대화 패널 안내와 실제 `01` 이동·미연결 결과의 차이를 반영했는가? |
| 추천 질문 예시 | 세 추천 질문이 모두 SecureCode 메인 예시로 이동하고 `15`에는 추천 버튼이 없음을 기록했는가? |
| 전송/복사/첨부 | 실제 메시지 처리·클립보드·파일 선택이 연결되지 않은 범위를 명확히 했는가? |
| 팝업 종료 정책 | 일반 팝업의 고정 `01` 복귀와 인덱스 확인의 `BACK`, 진행 화면의 미연결을 구분했는가? |
| 인덱스 진입과 실행 구분 | 확인 팝업을 여는 것만으로 인덱싱을 실행하지 않는 정책을 반영했는가? |
| 인덱스와 모델 독립성 | 모델을 불러오거나 질문할 필요가 없다는 설명과 `14 → 17` 연결을 반영했는가? |
| 인덱스 복수 선택 | 1개·2개 선택 예시와 실행 버튼 개수의 대응을 기록하고, 체크박스 미연결·0개 정책 부재를 명시했는가? |
| 인덱스 실행 경로 | 실행 버튼과 진행 화면 사이의 연결이 없으며 `18`·`19`는 별도 예시라는 점을 기록했는가? |
| 인덱스 진행률 | 64%는 현재 단계 파일 비율, 1/2 완료는 프로젝트 완료 수임을 분리했는가? |
| 인덱스 성공/실패 | 저장된 파일만 사용, 성공 후 새 인덱스로 교체, 실패 시 기존 인덱스 유지 정책을 반영했는가? |
| 인덱스 화면 닫기 | 닫기 버튼 미연결과 작업 취소·지속 정책의 미확인을 표시했는가? |
| 컴포넌트/화면 차이 | 단일 대상 컴포넌트의 `확인하고 시작`과 실제 복수 선택 화면의 `N개 생성·갱신`을 구분했는가? |
| 키보드 및 배경 처리 | 실제 연결된 Esc만 확인된 것으로 기록하고 Command+K·Enter는 안내와 구분했는가? 가려진 배경 버튼의 액션을 전면 동작으로 오인하지 않았는가? |
| 상태 보존 미정의 | 초안·스크롤·선택 모델의 전 화면 유지, 로딩 실패·검색 빈 결과·인덱스 부분 실패·재시도 정책을 임의로 확정하지 않았는가? |
| Rule ID 정합성 | 각 Rule ID가 중복 없이 정의되고, 흐름 요약과 마지막 목록이 본문의 실제 규칙을 참조하는가? |

위 체크리스트는 문서·프로토타입의 정합성을 검증하기 위한 기준이다. 미연결·불일치·정의 필요 항목은 각각의 CR·VR·ER 본문에 남겨 두었으며, 확인되지 않은 클릭 결과나 보존 정책을 확정 규칙으로 채우지 않았다.
