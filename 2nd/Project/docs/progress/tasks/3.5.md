## 구조

`apps/host/src`에서 routes는 SDK를 모른다. run service는 SDK 독립 포트 `cline/adapter/runtimePort.ts`의 `AgentRuntime`만 사용한다. `@cline/sdk` import는 `cline/` 아래로 제한된다(ESLint `no-restricted-imports`로 강제).

## 인수 근거

**조건 1 — 실제 SDK host의 실행/스트림/승인/취소와 UI API 계약**

- `sdkRuns.test.ts`(실제 ClineCore):
  - **완료:** `read_file` 도구를 실행한 뒤 답변하고 종료한다. 모든 SSE 이벤트가 `AppEvent` 계약을 통과하고, sequence가 1..n이며 `id:`와 일치한다. 상태는 `queued→running→completed`이고 snapshot이 계약을 통과한다. 첫 provider 요청의 tools는 4개 프로젝트 도구뿐이다.
  - **승인:** digest 불일치 거부, 거절 후 파일 미생성, 늦은 결정 `APPROVAL_ALREADY_DECIDED`, 승인 후 파일 기록을 확인했다.
  - **만료:** 300 ms 만료 뒤 늦은 승인은 `APPROVAL_EXPIRED`이고 명령은 실행되지 않는다.
  - **취소:** 승인 대기 중 취소하면 `cancelling→cancelled`, 승인은 `cancelled`, 늦은 승인은 거부된다. 명령 미실행이고 취소 뒤 provider 요청은 0회다.
- `hostServer.test.ts`:
  - health는 인증 전 최소 응답만 준다. 그 밖의 모든 경로는 cookie가 없으면 401이고, 외부 origin은 거부한다.
  - launch code는 한 번만 교환되며 cookie는 HttpOnly·SameSite=Strict·Path=/api다.
  - health 구성요소와 settings가 계약을 통과하고 비밀값·경로가 없다.
  - 작업 공간은 idempotent하고 경로를 echo하지 않는다. 상대·파일·없는 경로는 `FORBIDDEN`이다.
  - 64 KiB 초과는 `PAYLOAD_TOO_LARGE`이고, 3.6 경로 10개는 501과 owner를 반환한다.
- `devProxy.test.ts`: `createViteApiProxy` 설정과 같은 Host 재작성 proxy를 거쳐 bootstrap cookie·인증 JSON·SSE가 동작한다. 허용되지 않은 origin은 403이다.

**조건 2 — 세션·이벤트·중복 요청·재시작, 앱과 SDK 분리**

- `sdkSafety.test.ts`(실제 SDK):
  - 세션 A의 run이 승인을 기다리는 동안 두 번째 run은 409 `RUN_ALREADY_ACTIVE`(retryable, `active_run_id`)다.
  - 같은 key·같은 본문은 200으로 같은 run을, 같은 key·다른 본문은 `IDEMPOTENCY_CONFLICT`를 돌려준다.
  - 세션 B의 run은 독립적으로 완료된다. A의 스트림에는 A의 이벤트만 있다.
  - `Last-Event-ID: 3` 재연결은 4번부터 같은 이벤트를 주고, 마지막 sequence로 재연결하면 0건이다.
- `runLifecycle.test.ts`:
  - 종료 뒤 늦은 사실은 무시된다. 5,000자 답변은 4096+904 delta로 나뉘고, 종료 뒤 취소는 상태를 바꾸지 않는다.
  - **재시작:** 같은 데이터로 새 host를 띄우면 진행 중 run은 `failed`(`SERVICE_UNAVAILABLE`)가 된다. `active_run_id`는 비고, idempotency key는 유지된다. SSE는 `stream.replay_unavailable`(id 줄 없음) 뒤 종료한다.
  - replay 보존은 1,000개이고 이보다 이전 위치는 gap으로 처리한다.
- 분리:
  - routes·run service는 `AgentRuntime` 포트만 import한다. `FakeRuntime`으로 같은 route 시험이 통과한다.
  - SDK 이벤트 변환은 `coreEventMapper`가 맡는다. Core status와 `chunk`·`session_snapshot`은 전달하지 않는다.

**조건 3 — 포인터 hook/예산 포트, 로컬 도구 제한, 자동 commit/push/checkpoint 없음**

- hook·gate(`sdkSafety.test.ts`):
  - transformer 실패와 hang(500 ms timeout)은 run `failed`(`SERVICE_UNAVAILABLE`)로 끝난다. provider 요청은 1회이고 센티널 원문은 0건이다.
  - gate 거부는 `BUDGET_EXCEEDED`, gate 예외는 `TOKENIZER_UNAVAILABLE`이며 provider 요청은 0회다.
  - 16 KiB(`read_file` 기본 상한) 출력은 pointer로 교체된다. `run.pointer_created`가 생기고, 두 번째 요청·이벤트·snapshot에 센티널 원문이 0건이다.
- 운영 기본값: transformer와 gate가 null이면 보호 상태가 unavailable이고 세션 생성은 503이다. 시험과 실제 프로세스 체인 둘 다에서 확인했다.
- 도구 제한:
  - git commit·push(`-C` 옵션, `&&` 연결 포함)는 승인 요청 없이 거부되고 도구는 `failed refused`다.
  - 경로 이탈·`.git`·`.securecode`를 거부한다.
  - SDK 내장·provider 도구 11개는 disabled, 프로젝트 쓰기·명령 도구는 approval 필요다.
  - outbound 본문에 허용 목록 밖 도구가 있으면 차단한다. 명령 env에서 비밀값을 제거한다(`permissions.test.ts`).
- Git·checkpoint:
  - Git 저장소 작업 공간에서 승인된 파일 쓰기 뒤에도 `for-each-ref`·`stash list`가 같다.
  - start 설정은 `checkpoint.enabled=false`, `compaction=false`, MCP·spawn·teams off, `configExtensions: []`, `hookErrorMode: "throw"`, `interactive: true`다(`devProxy.test.ts` 두 번째 시험).
  - 소스에는 commit/push 실행 문자열이 없다(structure `git-mutation` PASS).

## 제한

- 시험의 transformer와 gate는 **fixture**(`tests/support/fixtureHooks.ts`)다. 운영은 4.4/4.8이 연결될 때까지 세션을 거절한다. 실제 provider·live `count_tokens`는 실행하지 않았다(3.6 `test:live`).
- Vite 자체는 UI 패키지(1.1)가 없어 실행하지 않았다. 같은 Host 재작성 규칙의 node:http proxy로 대신 검증했다.
- 브라우저 세션 토큰과 이벤트 replay 버퍼는 메모리에만 있다. host를 다시 시작하면 다시 bootstrap해야 하고, 이전 run은 snapshot만 남는다. SDK 대화 이력도 재시작 뒤 이어지지 않는다.
- `run_command`는 `shell: true`로 실행한다. Windows에서 timeout·abort 시 `kill`은 shell 자식 프로세스 트리를 모두 끝내지 못할 수 있다.
- 작업 공간 사이 도구 격리는 세션별 root 고정으로 구현했다. 서로 다른 작업 공간 두 개를 동시에 돌리는 시험은 없다.
- `run.context_planned`, `answer.citations`는 3.6에서 채운다. 지금은 빈 목록과 종료 페이지다.
