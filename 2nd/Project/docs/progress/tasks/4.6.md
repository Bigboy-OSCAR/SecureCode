## 이전 판정과 이번 재작업

2026-11-09 재검토는 4.6을 **BLOCKED**로 판정했다. 등록 시 전체 hash, 줄 조회 앞부분 scan, seek index, token cap, cursor, section/byte selector가 미완료였다. 3.6 재확인에서도 두 결함을 재현했다.

- P10: 20만 줄 끝 72바이트를 읽으려고 7.2 MB scan
- P11: `max_tokens`·cursor·selector 계약 없음

이번 작업은 `readers.py`·`search.py`를 다시 쓰고 기능별 모듈로 나눴다. 메모리 등록부 `store.py`와 `index.py`는 제거했다.

## 구현한 것

`services/context-service/src/securecode_context/pointers/source/`

| 파일 | 책임 |
| --- | --- |
| `io_meter.py` | 모든 원본 읽기를 64 KiB 이하 청크로 나누고 `bytes_read`·`max_chunk`·`seeks`를 계측 |
| `line_index.py` | 줄 오프셋 색인. 64 KiB 청크마다 첫 줄 시작 (줄, 위치)만 저장한다. 최초 생성은 순차 scan 1회이고, 이후 줄 위치는 checkpoint로 seek한 뒤 최대 64 KiB scan으로 찾는다. 마지막 줄의 LF/CRLF는 제외하고, 개행 없는 마지막 줄도 보존한다 |
| `markdown.py` | ATX 제목(#~######) 색인. 코드 펜스 안은 무시하고 줄마다 앞 512바이트만 본다. section은 정확히 같은 제목 하나에서 다음 같은/상위 수준 제목 직전까지다. 없거나 중복이면 `INVALID_SELECTOR` |
| `json_select.py` | JSON Pointer(RFC 6901). **8 MiB 이하 파일만 전체를 읽어 파싱**한다. 값은 재직렬화 문자열이라 selection이 없다. 초과하면 `PAYLOAD_TOO_LARGE(json_structured_limit)`이고 line/byte 읽기는 계속 가능하다 |
| `memo.py` | (source_id, revision, fingerprint, identity) 키의 색인 LRU. 원본이 바뀌면 키가 달라진다 |
| `caps.py` | 상한 검사(16,384 bytes / 32,768 tokens). UTF-8 문자 경계 자르기, 깨진 UTF-8 거부(`UNSUPPORTED_FORMAT(invalid_utf8, byte_offset)`). 토큰은 3.2 `TokenCounter`로 센 뒤 비율로 줄여 다시 센다(최대 8회, 길이/4 없음) |
| `read_cursor.py` | cursor를 workspace·source·요청 해시·revision·fingerprint에 묶는다. 다른 요청·원본·변조는 `INVALID_POINTER`, 바뀐 revision/내용은 `SOURCE_CHANGED` |
| `readers.py` | `SourceReader.read`. 순서는 resolve → 핸들 identity 확인 → 구간 계산 → 상한 안 읽기 → 핸들 identity 재확인 → resolve 재확인. 문자 중간 끝 byte 범위는 가장 긴 유효 앞부분과 `truncated`, 문자 중간 시작은 `INVALID_SELECTOR(utf8_boundary)`. PDF는 4.9 페이지 도구로 넘긴다 |
| `search_scan.py`, `search.py` | `SourceSearcher.search`. 리터럴 검색(실행 안 함)이며 한글 NFC·NFD 두 형태를 모두 찾는다. 버퍼는 64 KiB 청크와 문맥 120바이트다. 요청당 scan 8 MiB·2초 상한을 넘으면 `truncated`+cursor를 준다. 결과 수(≤100)·미리보기 bytes·tokens 상한을 넘으면 뺀 첫 일치에서 이어간다. 일치마다 줄 번호·byte_offset·원본 구간 selection(줄바꿈·CR 제외)을 준다 |
| `read_models.py`, `adapter.py` | 요청·결과 모델. `SourceAdapter(registry, reader, searcher)`가 3.6/4.8 인계 객체다 |

## 제한

- **최초 색인·검색은 순차 scan**이다. 줄 색인과 Markdown 제목 색인은 첫 조회 때 파일 전체를 64 KiB 청크로 1회 읽는다. 색인은 프로세스 메모리 LRU(32개)라 재시작하면 다시 만든다. 검색은 색인이 없으며 요청마다 최대 8 MiB를 scan하고 cursor로 이어간다.
- 반복 줄 조회는 회당 최대 약 128 KiB를 읽는다. 시작 줄과 다음 줄 위치를 각각 checkpoint에서 찾기 때문이다.
- JSON Pointer는 8 MiB 이하 전체 파싱이며, cursor 이어 읽기도 매번 다시 파싱한다. 값은 재직렬화 결과라 원본 selection을 줄 수 없다. 무제한 구조 조회가 아니다.
- Markdown은 ATX 제목만 지원하고 Setext 제목은 지원하지 않는다.
- **토큰 수는 TokenCounter가 있어야 한다.** 계수기가 없으면(현재 운영 기본값, 로컬 qwen 미지원) 비어 있지 않은 읽기·검색은 `TOKENIZER_UNAVAILABLE`이다. 시험은 `FixedTokenCounter`(바이트=토큰, `provider_estimate` 표시)로 했다. 실제 provider 계수와 로컬 모델 계수기는 4.8/3.6에서 연결한다.
- POSIX(`O_NOFOLLOW`) 열기 경로는 이 환경에서 실행하지 못했다(4.5와 같음). 3.7에서 macOS/Linux 실행이 필요하다.
- PDF 원본 읽기는 4.9 페이지 도구 범위이며 여기서는 `UNSUPPORTED_FORMAT(pdf_requires_page_tool)`이다. `pdf/tools.py`의 정규식 파서(P1~P4)는 4.9에서 고친다.

## 다음 인계

- **3.6**: host 공개 `POST /pointers/read`, `POST /pointers/search`를 `/internal/v1/source/read|search`로 프록시한다. host가 인증한 workspace_id를 넣는다. Cline의 source 읽기 도구는 이 경로로만 원문을 읽는다. `SourceAdapter`는 `app.state.source_adapter`에 있다.
- **4.8**: Context Selector가 Source 후보를 읽을 때 `SourceAdapter.reader.read(workspace_id, ReadRequest(pointer, Selector("byte"|"line", ...), max_bytes, max_tokens))`를 사용한다. 결과 `span`과 `record.fingerprint`로 "source hash + range" 중복을 판정한다(URI만으로 중복 제거하지 않는다. 3.6 재현 P5). token_count와 count_mode를 그대로 예산에 쓴다.
- **4.9**: 텍스트 읽기는 PDF를 거부한다. 페이지 텍스트는 파생 캐시(`DerivedCacheDirectory`·`registry.attach_derived`)에 두고, 페이지 읽기에는 같은 `caps.fit_text`와 `read_cursor`를 재사용할 수 있다.
