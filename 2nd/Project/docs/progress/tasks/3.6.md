## 시도하지 않은 것과 이유

- Selector·Gate·Source·PDF·Runtime 정책을 host에서 대신 구현하지 않았다. 다른 담당자의 정책을 중복 구현하는 것은 금지다(수행할 일 7, 3.5 수행할 일 5).
- fixture adapter를 운영 경로에 연결하지 않았다. 완료 조건 1에 따라 mock 경로가 남으면 안 된다.
- R0 부분만 먼저 연결하는 작업도 하지 않았다. 해당 범위는 아래와 같다.
  - `/internal/v1/symbols/*` route
  - host `SymbolService` client
  - index API
- 이 범위는 Selector·Gate 없이 운영 경로를 증명할 수 없다. 3.6 완료 조건도 세 기능을 함께 요구한다. 그래서 선행 완료 뒤 한 번에 조립·검증한다.

## 제한·재개 방법

1. 임우형이 4.4, 4.6, 4.8, 4.9를 완료하고 각 `docs/progress/tasks/<번호>.md`와 로드맵 체크를 남긴다. 4.6은 4.5, 4.8은 4.7, 4.4는 4.3을 선행으로 둔다.
2. 실제 provider smoke를 위해 서버 환경에 `ANTHROPIC_API_KEY`를 설정하고, `SECURECODE_LIVE_SMOKE=1`과 호출 상한 `SECURECODE_LIVE_SMOKE_MAX_CALLS`를 준비한다. 키는 커밋하지 않는다.
3. 같은 3.6 프롬프트를 다시 실행한다. 이번에 확인한 선행 상태부터 다시 점검하고 남은 범위만 처리한다. 3.6이 소유하는 연결점은 다음과 같다.
   - `apps/host/src/app/main.ts`의 `transformer`/`gate` 교체
   - `routes/pendingRoutes.ts`의 index·pointer·context·pdf 10개 경로
   - `RunService.create`의 `context_refs`·`preview_digest` 거절 해제
   - `WorkspaceRegistry.rootFor` → Python `WorkspaceRootPort`
   - host `SymbolService`/`PointerService` client의 `pendingOperation`
   - 위치와 계약은 [3.5 인계](../handoffs/3.5-host-api-and-fixtures.md) 5절에 있다.
