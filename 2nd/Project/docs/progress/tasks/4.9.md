## 라이브러리 검증

`pypdf` 6.21.4를 의존성에 추가했다(`uv add "pypdf>=5,<7"`, BSD). 이유는 다음과 같다.

- 순수 Python이다.
- FlateDecode·page tree·ToUnicode(CID 글꼴)·암호화 감지를 지원한다.
- PyMuPDF는 AGPL이라 제외했다. pdfminer.six는 더 크다.

생성 fixture로 직접 확인한 결과:

- 한글 CID 텍스트를 정확히 복원한다(문자열 일치).
- page tree 순서가 맞다(객체를 거꾸로 만든 PDF).
- `is_encrypted`가 맞게 감지된다.
- 손상 파일은 예외가 난다.

## 인수 근거

| 완료 조건 | 근거 |
| --- | --- |
| 텍스트 PDF가 페이지 캐시와 Source Pointer로 연결되고 전체 본문을 반환하지 않는다 | 등록한 Source → `pdf/parse`는 `ready`, `page_count=3`이다. 상태 JSON에 페이지 문자열·sentinel이 없다. 캐시는 원본 해시+파서 버전 키 하나다. 2페이지 읽기에는 1·3페이지 sentinel이 없다. `pdf_page` selection(페이지 2·파서 버전·원본 해시, 폭 = 본문 바이트)이 맞다. 1~3페이지 범위는 24바이트 상한으로 한 페이지씩 cursor로 이어진다. 해제하면 캐시가 지워진다. host `pdf_parse` 출력 키는 `job_id/page_count/state`뿐이다 |
| 실제 PDF 도구 계약과 SKILL.md 지침·등록 export 일치 | `pdfPointerSkill.test.ts`가 다음을 확인했다. <br>- `SKILL.md` SHA-256·도구 이름·입력 필드가 `registration.json`과 `pdfTools` 레지스트리와 같다 <br>- 표에 없는 도구 이름이 있으면 로더가 거절한다 <br>- `withSkills`가 marker와 함께 prompt에 붙인다 <br>`pdfTools.test.ts`는 실제 서비스로 도구를 실행해 SKILL 예시와 같은 출력 모양을 확인했다 |
| 한글/페이지 범위/출처/캐시 갱신/미지원/손상·취소 시험 | 한글 CID 본문, page tree 순서, `partial`(빈·스캔 페이지 제외와 건너뛰기), 스캔·빈·암호화·501쪽은 `unsupported`, 손상은 `failed/damaged`, 각각 읽기 거절을 확인했다. 같은 원본은 job·캐시 재사용이다. 원본이 바뀌면 `stale/source_changed`와 `SOURCE_CHANGED`이고, refresh 후 새 job이 새 내용을 읽으며 이전 캐시는 지워진다. 시간 초과는 `failed/timeout`이고 캐시·작업 폴더가 없으며 재시도하면 `ready`다. 취소된 job은 조회되지 않고 작업 폴더가 비고, 프로세스가 kill된다. 검색은 페이지 출처를 단다. Selector는 PDF 페이지 fragment를 넣고, 원본이 바뀌면 `stale`과 `SOURCE_CHANGED`다 |

## 제한

- 생성 fixture만 시험했다. Identity-H CID 글꼴과 ToUnicode를 쓴 PDF다. 실제 문서는 확인하지 않았다(simple/Type1 글꼴, ToUnicode 없는 글꼴, 다단 레이아웃, 합자). pypdf 추출 품질은 문서마다 다를 수 있다.
- `size_limit`은 4.5 등록이 50 MiB 초과를 먼저 거절하므로 parse에서는 나오지 않는다.
- job 기록은 메모리에만 있다. 서비스를 재시작한 뒤 이전 job ID는 `NOT_FOUND`다. 다시 parse하면 캐시로 바로 `ready`다.
- `idempotency_key`는 형식만 확인한다. job은 원본 해시로 정한다.
- 계약에 `cancelled` 상태가 없어서 취소한 job은 기록을 지운다(`NOT_FOUND`).
- PDF 검색은 cursor 없이 최대 50개, `truncated` 표시만 한다.
- 파싱마다 spawn 프로세스를 띄운다(Windows에서 약 1초 추가). POSIX에서는 실행하지 않았다.
- host 공개 `/pdf/*` route, 세션 도구 등록, system prompt 연결은 3.6 몫이다. 이번에는 export와 검증 fixture까지만 했다. SDK 세션에서 모델이 이 skill로 PDF를 읽는 live 실행은 하지 않았다.
- 4.10의 저장소 루트 `tests/integration/test_pointer_context_pdf_integration.py`는 이번에 지운 PDF 클래스도 import한다. 4.10이 다시 써야 한다.
