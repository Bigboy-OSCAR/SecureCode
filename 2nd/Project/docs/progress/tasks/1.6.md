### 답변 근거 (UI23-05, E2E 마지막 단계)

- host는 run마다 근거 목록을 만든다. 넣는 것은 두 가지다.
  - run 생성 때 `context.select`가 넣은 fragment의 provenance
  - 모델이 도구로 실제로 읽은 범위: `read_file`, `pdf_read_pages`의 selection, `code_search` 뒤 `code_read`의 위치
- 각 근거는 `SessionContextStore.beginRun/cite/endRun` → `RunRecorder.cite`(중복 제거, 최대 200)로 기록한다.
- 스냅샷은 `citations`/`citations_page`를 페이지로 나눠 준다. 원문은 들어가지 않는다.
- UI는 SSE에 근거가 없으므로 terminal 이벤트 뒤 스냅샷에서 근거 목록만 다시 받는다(`RunController.refreshCitations`).

## 남은 것 (재개 방법)

1. **2.3 로드맵 체크 복원**: 김찬우가 `ef2137ae`의 체크를 되살리거나 팀이 합의한다.
2. **AC-03 새로고침 뒤 선택·세션 복구**: 현재 UI는 새로고침하면 프로젝트 선택과 세션을 잃는다. host에 세션 목록 API가 있으므로 UI 구현으로 해결된다.
3. **AC-02**: 만료·재사용 코드, 실행 중 인증 만료 뒤 같은 run 복구를 E2E로 확인한다.
4. **AC-08·12**: 응답 유실·새로고침 뒤 run 보존, 색인·PDF 상태 재조회를 E2E로 확인한다.
5. **AC-15**: 입력 digest 변경·다른 scope 결정을 화면으로 확인한다.
6. **AC-18·25·32**: 목록 종류 탭·필터, JSON 경로와 8 MiB 초과 JSON, 설정 변경 뒤 재조회와 미설정 전송 차단.
7. **AC-33**: 스크린리더(NVDA 등) 낭독과 명도 대비 측정. 이 환경에서는 자동화하지 않았다.

위를 마친 뒤 `npm run test:e2e`, `npm run check`, `SECURECODE_LIVE_SMOKE=1 npm run test:live`를 다시 실행하고, 인수표 9절과 로드맵 1.6을 갱신한다.

## 제한

- E2E 모델은 fixture다. 도구 호출 순서는 대본대로이고, 실제 모델의 판단은 live로만 확인했다.
- live는 로컬 Qwen 한 모델이다. 같은 smoke가 실행마다 다른 단계에서 실패할 수 있다(2회 시도 허용).
- E2E는 Windows의 Edge로만 실행했다. Chrome·POSIX는 `SECURECODE_E2E_BROWSER`로 바꿀 수 있지만 실행하지 않았다.
- 개발 데이터 폴더(`.securecode`)에 시험용 작업 공간 `ws15`가 남아 있다.
- 실행 종료 메시지(`the model run stopped (error)` 등)는 host 영문 문구 그대로다.
