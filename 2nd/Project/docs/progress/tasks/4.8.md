## 제한

- **live 미검증**:
  - 실제 Anthropic `count_tokens`에 전체 요청을 보낸 적이 없다(API 키 없음). 본문 구성은 MockTransport로만 확인했다.
  - SDK 시험의 계수기는 시험용 `FixedTokenCounter`다(입력 JSON UTF-8 바이트 = 토큰, `provider_estimate`).
  - 실제 provider 계수와 실제 사용량의 차이는 3.6/3.7 live smoke에서 확인해야 한다.
- **로컬 qwen-2.5**: framing·계수기가 없다. Selector와 gate 모두 `TOKENIZER_UNAVAILABLE`로 막힌다. 쓰려면 같은 tokenizer와 chat template framing을 검증한 `RequestTokenCounter`가 필요하다.
- **hard-cap 기본값**: `SECURECODE_REQUIRE_FINAL_TOKEN_COUNT=true`가 기본이다. 지금은 `exact` 계수 모델이 없으므로 운영 run은 모두 `TOKENIZER_UNAVAILABLE`로 막힌다. 추정+마진으로 쓰려면 false로 둔다.
- **chain 통합**: 키가 없어 SDK가 fetch 전에 멈춘다(`PROVIDER_ERROR`). 운영 host gate의 실제 결정은 chain에서 보지 못했다. SDK 시험이 대신 확인한다.
- **R0 연결**: R0는 앱에 아직 연결되지 않았다. 심볼 resolver는 시험에서 실제 색인으로만 확인했다. host 미리보기·run 생성에서 Selector를 부르는 일과 `history_refs`·비용 텍스트를 모으는 일도 3.6 몫이다.
- **선택 범위 정렬**: 명시 selection 끝이 UTF-8 문자 중간이면 경계까지만 읽는다. 끝에서 3바이트 이내면 읽은 것으로 본다. 정상 경로의 selection은 읽기 결과에서 오므로 경계에 맞는다.
- **심볼 중복**: 시작 심볼 범위로만 비교한다. 묶음의 참조 심볼까지 비교하지는 않는다.
- **도구 결과 연결**: gate가 남긴 여유로 줄이는 것은 `runtime_read`뿐이다. `read_file` 등 다른 도구 결과는 4.4 포인터 교체와 다음 호출 gate로 막는다.
- **다른 작업의 파일**:
  - `ruff format`을 `src` 전체에 잘못 실행했다. 변경 전이던 `pdf/cache.py`·`pdf/parser.py`는 HEAD로 되돌렸다.
  - `pdf/tools.py`는 4.5에서 바꾼 상태 위에 서식만 바뀌었다(동작 변경 없음).
  - 4.10의 저장소 루트 `tests/integration/test_pointer_context_pdf_integration.py`는 4.5/4.6 때부터 이미 없는 클래스를 import한다. 이번에 지운 `ContextBudgetCalculator` 등도 import한다. 어떤 스크립트도 실행하지 않으며 4.10이 다시 써야 한다.

- `SECURECODE_MODEL_CONTEXT_LIMIT`은 서버 `-c`보다 크면 안 된다. 자동으로 확인하지 않는다.
- Selector 고정 비용·fragment 계수는 `plain_text`(메시지 framing 없음)다. 최종 요청은 gate가 framing까지 포함해 다시 센다.
