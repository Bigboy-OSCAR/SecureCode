## 이전 판정과 이번 재작업

2026-11-09 재검토는 4.4를 **BLOCKED**로 판정했다. 남은 조건은 4.3 선행 재검증과 executor streaming 저장·잘림 정책 인수였다. 4.3이 2026-11-10에 DONE이 되어 이어서 진행했다. 기존 구현에는 다음 문제가 있었다.

- host가 옛 숫자 offset 경로를 썼다.
- `runtime_search`가 앞 16 KiB만 클라이언트에서 검색했다.
- 명령 출력을 1 MiB까지 메모리에 모았다.
- 별도 legacy plugin(`createRuntimePointerPlugin`)이 있었다.
- `api: "legacy"` 분기가 있었다.

추가로 확인한 것:

- 삭제·만료·세션 종료 포인터는 원문 대신 `NOT_FOUND`/`EXPIRED`가 된다. 실행 중 세션 정리 → 도구 오류 `NOT_FOUND`, 만료(DB 시각 조작) → `EXPIRED`, `closeSession` → `NOT_FOUND`.
- JSON 출력의 status·exit code·도구 오류 표시는 descriptor에 남는다(transformer 시험).

## 제한

- **운영 세션은 여전히 차단**된다. `main.ts`의 `gate`는 4.8 전까지 null이며, Runtime 보호(`runtime_pointer_hook`)만 준비 상태다.
- **토큰 계수기**: 계약형 `runtime_read`/`runtime_search`는 TokenCounter가 필요하다. 운영 기본값에는 계수기가 없어 `TOKENIZER_UNAVAILABLE`로 막힌다. 시험은 실제 서비스 앱에 `FixedTokenCounter`를 넣은 시험 전용 진입점으로 했다. 로컬 qwen 계수기 연결은 4.8/3.6에서 한다.
- **시험 범위**: 실제 provider 호출은 하지 않았다(3.1 scripted provider). live smoke는 3.6 범위다.
- **스트리밍 잘림 표시 방식**: 스트리밍 저장은 시작 시점에 잘림 여부를 모르므로 서비스 provenance의 `truncated_before_storage`는 false다. 잘림은 descriptor와 저장 객체 끝의 표시로 정확히 남긴다. JSON 저장 경로(afterTool)는 처음부터 표시한다.
- **명령 출력 디코딩**: UTF-8이 아닌 명령 출력(예: Windows 코드페이지)은 U+FFFD로 바뀐다(이전 동작과 같음).
- **Source·PDF 실제 도구 미검증**: 4.2 fixture로 정책만 검사했다. 실제 도구 연결과 검증은 3.6/4.9에서 한다.
- POSIX의 process group 종료 경로와 `O_NOFOLLOW`는 이 환경에서 실행하지 못했다. 3.7에서 확인이 필요하다.
