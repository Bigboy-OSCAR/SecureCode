## 5. limitations

- **Node LTS 미검증:** 3.1 인계는 3.2에 Node 22/24 LTS 고정과 probe 재실행을 요구했다. `engines`와 `.nvmrc`는 고정했지만 이 PC에는 Node 26.13만 있고, LTS 런타임 다운로드가 환경 권한으로 거부됐다. 모든 실행은 Node 26에서만 했다. LTS가 설치된 팀원이 `npm ci && npm run probe:sdk && npm run check`를 실행해야 한다(3.7에서 확인).
- **live tokenizer 미검증:** `tokens.count`는 실제 Anthropic `count_tokens` 호출을 구현했지만 키가 없어 scripted provider(httpx MockTransport)로만 검증했다. live 결과를 성공으로 기록하지 않았다. `test:live`는 SKIPPED다(4.8/3.6에서 실행).
- **legacy 포인터 코드:** strict SDK 타입 오류 23개, 구조 위반 23건, docstring 미적용 10개 파일은 KNOWN이다. 3.2는 담당자 파일을 고치지 않았다. 그 결과 `check`는 3.7 전까지 exit 0이 될 수 없다.
- **보안 일부는 계약만 확정:** bootstrap cookie, settings, run/approval/SSE는 501 상태이며 3.5에서 구현한다. 현재 host health는 bootstrap 전 최소 응답만 지원한다.
- `npm audit` 운영 의존성 25건(대부분 `@cline/sdk` 전이 의존성)은 SDK 버전 고정 때문에 바꾸지 않았다. Starlette TestClient의 httpx deprecation 경고가 있다(동작 영향 없음).
- 이 환경에서는 uv를 사용자 Python(3.11)의 PyPI 패키지로 설치했고 PATH에 수동으로 추가했다. 팀원은 README 절차로 uv를 설치한다.
