## 실행 범위

`services/context-service`에서 아래 명령으로 로컬 프로젝트의 색인을 생성한다. 입력은 파일당 최대 1 MiB의 UTF-8 소스다. [언어별 확장자와 심볼 범위](../../../INTEGRATED_SYSTEM_IMPLEMENTATION_ROADMAP.md#01-요구-해석과-이번-프로젝트의-완료-범위)는 로드맵 0.1을 따른다.

```bash
uv run python -m securecode_context.symbols <프로젝트_디렉터리> --out <색인.json>
```

`nodes`에는 파일·줄·바이트 범위·원문·SHA-256과 해결된 참조 및 미해결 참조가 들어간다. `raw`에는 심볼 단위 원문과 최대 3단계까지 따라간 정적 참조 묶음이 들어간다. 파일별 실패·미지원 사유는 `diagnostics`에서 확인한다. 재생성하면 완성된 JSON으로 출력 파일을 교체한다.

## 실행 검증

| 검증한 입력과 조작 | 확인한 결과 |
| --- | --- |
| Python, C, C++, Java, JavaScript만 각각 넣은 프로젝트 5개에 CLI 실행 | 다섯 번 모두 해당 언어의 심볼과 R0 후보 생성 |
| 다섯 언어와 오류 파일이 섞인 프로젝트 1개에 CLI 실행 | 심볼 11개, 후보 17개 생성. 깨진 C 파일과 TypeScript 파일은 각각 `syntax_error`, `unsupported_language`로 기록 |
| 위 JSON의 `nodes`와 원본 파일 대조 | 심볼 11개 모두 원문 바이트 범위·시작 줄·파일 해시 일치 |
| 위 JSON의 `raw[].source_uris` 대조 | Python 함수→다른 파일 helper→상수, C 함수→헤더 상수, C++ 함수→헤더 클래스, Java 클래스→같은 패키지의 클래스, JavaScript 함수→다른 모듈의 별칭 import가 예상한 파일로만 연결 |
| 기존 Python 실험 고정 프로젝트 7개의 R0 후보와 필드별 비교 | 후보 314개가 기존 출력과 일치 |
| 혼합 프로젝트의 `raw`를 기존 R0 TF-IDF 검색기에 전달 | 다섯 언어 각각의 식별자 검색에서 해당 심볼이 1위 |
| 같은 출력 경로로 재실행 후 파일 변경·이동·삭제 | 동일 입력의 JSON이 바이트 단위로 일치. 변경된 해시와 새 경로를 반영하고 삭제된 심볼을 제거 |
| context-service의 `.venv/bin/pytest -q` 및 `ruff check .`, `mypy src` | 서비스 테스트 176개 통과(실제 프로세스 기동 포함). lint·타입 검사 통과 |

변경한 JSON·생성 TypeScript 파일의 포맷과 생성 타입 최신 여부를 확인했다. 프로젝트 전체 Prettier 검사에서는 이번 수정 범위 밖의 기존 포인터·컨텍스트 계약 파일 21개가 포맷 경고를 낸다.

로컬 JSON 생성과 서비스 revision 관리는 별도 단계다. 작업 공간별 인덱스 상태, 오래된 revision 거부, 원자적 서비스 전환과 검색·웹·SDK 연결은 후속 검증이 필요해 3.3/3.4 완료 체크를 열어 둔다.
