## 구현 범위

- Ajv 기반 JSON Schema 검증과 camelCase/snake_case 변환을 `apps/ui/src/api/mappers/contractMapper.ts` 경계에 모았다. typed HTTP client와 SSE client는 분리했고 네트워크, timeout, 401/403, 5xx, 잘못된 계약 응답을 별도 오류 종류로 전달한다.
- bootstrap 일회용 코드는 POST 본문으로만 보내며 입력은 교환 직후 지운다. HTTP와 SSE는 same-origin credentials를 사용하고, provider 키나 내부 토큰을 브라우저 저장소에 요구하거나 보관하지 않는다. 오류 UI는 원본 응답 본문을 표시하지 않는다.
- 워크스페이스 등록, 세션 생성, run 생성/조회, 취소, 승인 결정, 이벤트 스트림을 host API에 연결했다. 중복 생성 요청은 안정적인 `idempotency_key`를 재사용한다.
- SSE는 `Last-Event-ID`로 재접속하고 sequence/ID를 검증·중복 제거한다. replay 만료는 authoritative run snapshot을 조회해 복구한다. SSE 단절만으로 cancel API를 호출하지 않는다.
- `LiveApp`에서 실제 host 흐름을 연결하고 index/pointer/PDF 등 아직 제공되지 않는 기능은 성공처럼 보이지 않도록 unavailable/readiness 상태로 표시한다.
- 실제 host와 설치된 Cline SDK의 scripted provider fixture 통합 시험에서 답변·tool event·snapshot·승인 거절·취소를 확인했다. 첫 SSE 연결을 의도적으로 끊고 host에 `Last-Event-ID: 1`로 재접속해 replay를 받았으며 이벤트 sequence가 연속이고 duplicate run/tool 실행이 없음을 검증했다. 이 결과는 fixture provider 실행이며 외부 실제 provider 실행으로 간주하지 않는다.

## 인수 근거와 제한

- UI API boundary 시험은 잘못된 성공/오류 payload를 거부하고 원문 오류 본문을 숨긴다. 일회용 연결 코드는 URL이나 browser storage에 들어가지 않으며 same-origin cookie 연결을 사용한다.
- UI client → 실제 host → 설치된 Cline SDK 통합 시험은 워크스페이스/세션/run 중복 요청이 동일 ID를 재사용하는지 확인한다. run 생성 중복 뒤 provider 요청 수가 단일 SDK run과 일치하고, stream 재접속 커서가 `0`에서 `1`로 진행하며 terminal event까지 sequence가 연속임을 확인한다.
- 승인 거절 뒤 보호 대상 파일이 만들어지지 않고, 취소 뒤 run이 `cancelled`로 끝나며 취소된 도구가 실행되지 않는다. UI client와 `RunController`가 실제 host 응답/이벤트를 소비한다.
- `docs/progress/tasks/3.5.md`에 기록된 대로 운영 host는 protection budget gate가 등록되지 않은 상태에서 세션 생성에 fail-closed한다. 본 과업은 gate를 우회하지 않았고 production provider run을 하지 않았다. roadmap 0.8이 규정한 actual SDK + scripted provider 검증 기준으로 1.4 완료를 판정했다.
- 실제 브라우저 E2E 및 외부 provider 검증은 수행하지 않았다. 완료된 범위는 UI API client/RunController와 실제 host/SDK 통합이다. Vite main chunk 용량 경고는 향후 번들 분할에서 다룰 수 있다.
