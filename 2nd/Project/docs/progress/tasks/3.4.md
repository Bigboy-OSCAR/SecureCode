## READY 전환

`SymbolIndexService.build()`는 다음 순서로 동작한다.

1. 스캔하고 revision 기록을 만든다.
2. `prepare_retrieval()`로 모든 후보(atomic과 깊이 3 bundle)의 TF-IDF 벡터와 메타데이터를 만든다.
3. `retrieval={state:"ready", candidate_count, vocabulary_size}`를 기록한 뒤 revision을 게시한다.

벡터 준비가 실패하면 게시하지 않고 이전 revision을 유지한다. 따라서 검색에 노출되는 revision은 항상 벡터까지 준비된 것이다. 벡터는 디스크에 저장하지 않는다. 재시작 뒤 첫 검색에서 같은 후보 텍스트로 다시 만든다(결정적). 형식상 `pending`인 기록이 current이면 검색은 HTTP 200 `no_match.hint="index_not_ready"`를 반환한다. 상태 응답은 `ready`, 진단이 있으면 `partial`이며 `searchable=true`다.

## 무결과·0점 처리 (실험과의 차이)

실험의 `pack()`은 점수가 0인 후보도 순위대로 예산이 찰 때까지 채웠다. 제품은 다음과 같이 다르다.

- 점수가 0보다 큰 후보만 반환한다.
- 검색어에서 토큰을 추출할 수 없거나(한국어만 있는 질문 포함) 모든 점수가 0이면, 빈 `candidates`와 `no_match={"reason_code":"NO_MATCH","hint":"try_identifier_or_file_name"}`를 반환한다. HTTP 200 본문 계약이다.
- 안내 hint는 영어 식별자·파일명 입력이나 사용자 범위 선택을 유도하는 UI 문구에 쓴다.
- 심볼이 없고 미지원 언어 파일만 있으면 `unsupported_language_only`를 반환한다.
- 이 경로들에서는 TokenCounter도 호출하지 않는다.

## 크기·중복·stale 정책

- **검색:** 후보는 최대 100개다. 페이지는 기본 20개, 최대 100개다. 응답 본문은 64 KiB에서 멈추고 `truncated_by_bytes`를 표시한다. 후보에는 원문이 없고 ID·위치·점수·깊이·`estimated_tokens`만 들어간다. 추정 토큰은 그 페이지 후보만 주입된 TokenCounter로 센다.
- **중복:** 앞 순위 후보들이 이미 모든 원문 범위(파일 해시+바이트 범위)를 포함한 후보는 뺀다. 이는 실험 pack의 `set(source_uris) <= raw_sources` 제외와 같은 규칙이다. 순환 `ping↔pong`의 두 bundle은 같은 범위라 함께 빠진다.
- **묶음:** `max_bytes`는 최대 32 KiB이고 `max_tokens`는 필수다.
  - 시작 심볼부터 BFS 순서로 넣는다. 넘치는 심볼은 `budget_exceeded`, 한 fragment가 바이트 상한을 넘으면 `too_large`로 누락한다.
  - 시작 원문이 들어가지 못하면 참조만 보내지 않는다. 대신 atomic 후보나 더 큰 예산을 사용하게 한다.
  - 고른 원문을 `\n\n`으로 이어 다시 계수하고, 상한을 넘으면 뒤에서부터 뺀다.
  - 후보 밖으로 밀린 참조는 `depth_limit`·`too_large`로 함께 알린다.
- **stale:**
  - 원문을 반환하기 직전 revision과 디스크 파일 해시를 다시 확인한다.
  - 시작 심볼 파일이 바뀌었으면 `SOURCE_CHANGED`, 참조 파일이 바뀌었으면 그 fragment를 `stale_revision`으로 누락한다.
  - 이전 revision의 후보·`index_revision`·cursor는 모두 `SOURCE_CHANGED`다.
- **최종 전체 모델 요청 예산:** 4.8 범위다.

## 제한

- TokenCounter는 시험에서 고정 계수 fixture(`FixedTokenCounter`, UTF-8 바이트=토큰, `provider_estimate` 표시)로만 검증했다. 실제 provider 계수기(`AnthropicTokenCounter`, 3.2)와의 live 계수는 API 키가 없어 실행하지 않았다. 계수기를 사용할 수 없으면 검색·묶음은 `TOKENIZER_UNAVAILABLE`로 실패한다.
- 내부 HTTP route(`/internal/v1/symbols/*`)와 host `SymbolService` 연결은 하지 않았다. 작업 공간 ID→루트 등록부(3.5)가 필요하다. host는 계속 `NOT_IMPLEMENTED`(owner 3.6)를 반환하고, health의 `symbols`도 `not_implemented`(owner 3.6)다.
- `WorkspaceRootPort`의 기본 구현은 fixture(`StaticWorkspaceRoots`)뿐이다.
- 검색마다 전체 후보를 다시 점수화한다. 결과 캐시는 없다.
- fragment `content`는 색인한 바이트 범위의 원문만 담는다. 실험 fragment의 위치 헤더·import 줄은 넣지 않으며, 위치는 `start_line`/`end_line`/`provenance`로 전달한다. 검색 벡터는 실험과 같은 후보 텍스트(헤더·import 포함)로 만든다.
