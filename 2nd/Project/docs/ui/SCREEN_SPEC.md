# 제품 화면·사용 흐름 설계

> 작업: 2.1 → 2.2 → 2.3 검토 보완 · 담당: 김찬우 · 문서 버전: 3 · 작성일: 2026-10-30 · 보완일: 2026-11-09 (Asia/Seoul)
>
> 상태: 화면 설계. 실행 가능한 UI나 확정 API 스키마를 의미하지 않는다.
>
> 기준: [로드맵 0절·2.1절](../../INTEGRATED_SYSTEM_IMPLEMENTATION_ROADMAP.md), [코딩컨벤션](../../CODING_CONVENTIONS.md)

이 문서는 화면 구조·와이어프레임·지원 범위의 정본이다. 화면 ID는 `SC-01`, 사용자 시나리오 ID는 `UI-01`, 계약 요청 ID는 `H-01` 형식으로 유지한다. [사용자 시나리오](USER_SCENARIOS.md)와 [2.1 계약 인계](../handoffs/2.1-ui-contract-requirements.md)는 초기 요구를 보존한다. 확정된 필드·입력 검증·버튼·문구는 [UI_BEHAVIOR](UI_BEHAVIOR.md), 실제 fixture와의 대응은 [UI_BEHAVIOR_CASES](UI_BEHAVIOR_CASES.md)를 따른다. 구현 화면의 검토 결과와 최종 인수 절차는 [ACCEPTANCE](ACCEPTANCE.md)에 기록한다.

**2.2 인계.** 9개 화면의 표시·입력·복구 규칙은 [상세 명세](UI_BEHAVIOR.md), 계약 예시와 사용자 행동의 대응은 [34개 사례](UI_BEHAVIOR_CASES.md)에 있다. 호스트가 501을 반환할 때는 해당 기능을 준비 중으로 표시한다.

**2.3 검토 기준.** fixture 화면은 설계의 표시 예시와 일부 사용자 동작을 검토하기 위한 입력이다. 서로 다른 오류 예시를 펼쳐 보는 것은 해당 오류의 실제 발생·복구 검증이 아니다. 표본 상태는 현재 작업 상태와 명확하게 구별하고, 같은 자료의 정상 결과에 무결과·만료·원본 변경을 동시에 붙이지 않는다. 인수표의 fixture 검토 결과와 1.4/1.5의 실제 연결 및 1.6/3.8의 최종 제품 통과는 구분한다. 미구현 조작은 [2.3 수정 요청](../handoffs/2.3-ui-review-fixes.md)에 인계하며 문서 요구를 제거해 통과시키지 않는다.

## 1. 사용자 목적과 범위

사용자는 자신의 컴퓨터에서 프로젝트를 등록하고 R0 코드 색인을 만든다. 식별자나 파일명을 포함한 질문으로 관련 코드와 출처를 확인하고, 필요한 코드 수정·명령 실행을 건별로 승인한다. 등록 자료와 저장된 실행 결과는 필요한 범위만 읽어 질문에 선택할 수 있다. 무엇을 읽었고 무엇이 제외됐는지, 실행이 끝났는지, 다음에 어떤 조작을 할 수 있는지가 항상 보여야 한다.

| 제품 용어 | 화면 문구 | 표시 원칙 |
| --- | --- | --- |
| Cline SDK / host / context-service | 코드 작업 도구 / 로컬 서비스 | 내부 클래스·hook 이름은 기본 화면에 노출하지 않는다. 오류 식별 번호와 복구 행동은 제공한다. |
| R0 / Symbol Bundle | 관련 코드 | 지원 언어의 심볼 원문과 최대 깊이 3의 정적 참조 묶음. 검색 점수는 관련도 순서이며 정답 확률이 아니다. |
| Source Pointer | 등록 자료 | 파일 원본을 보관한 위치를 참조한다. 삭제 조작의 이름은 **등록 해제**다. |
| Runtime Pointer | 실행 결과 | 큰 도구 출력을 저장한 결과. 세션·보관 기한·크기를 함께 표시한다. |
| Context Selector / token budget | 전달할 자료 / 입력 예산(토큰) | 선택·제외 이유와 추정/검증 여부를 보여 준다. 선택한 자료도 한도를 초과할 수 없다. |

지원 안내는 프로젝트 등록과 관련 코드 패널에 상시 제공한다. 지원 목록은 `Workspace.supported_languages`를 화면 이름으로 표시한다. 다섯 언어를 지원하는 경우 “Python, C, C++, Java, JavaScript 코드에서 관련 심볼과 확인 가능한 로컬 참조를 찾습니다. 메서드는 클래스 원문에 포함될 수 있습니다.”로 안내한다. `unresolved_reference`는 “확인하지 못한 참조”로 설명한다. TypeScript 파일은 자료 등록·부분 조회를 안내한다. 한국어 질문의 의미를 자동 번역하지 않으므로 무결과일 때 함수명·파일명 입력을 안내한다.

포함 기법은 R0 원문 TF-IDF 검색, Source Pointer, Runtime Pointer다. Context Selector와 PDF는 조정·추출 계층이다. RAPTOR, RF/RH 요약 트리, H의 LLM 후보 선택, 임베딩/벡터 DB, Self-Extend, 별도 에이전트 프레임워크, 클라우드 배포, 다중 사용자 협업, OCR, 암호화 PDF 해제는 제외한다. 준비 단계 요약·LLM 후보 재선택은 0회이며 전체 파일 자동 전송·자동 요약·자동 승인을 추가하지 않는다.

1. 로컬 실행 안내에 따라 서비스를 시작하고 SC-01에서 일회용 코드로 연결한다. 계정 가입 화면은 없다.
2. SC-09에서 서비스와 모델 설정 상태를 확인한다. 모델 설정이 없어도 프로젝트·자료 준비는 가능하며 모델 실행은 차단한다.
3. SC-02에서 경로를 직접 입력해 프로젝트를 등록하고 색인을 만든다. 준비된 색인과 사용 가능한 파일 범위를 확인한다.
4. SC-03에서 세션을 만들고 질문한다. 필요하면 SC-06/SC-08에서 자료를 등록하고 SC-07에서 선택한 범위를 SC-09에서 미리 확인한다.
5. SC-04의 승인 요청이 있으면 대상과 내용을 확인해 승인 또는 거절한다. 진행 중에는 SC-03에서 취소를 요청할 수 있다.
6. 답변의 출처는 SC-05/SC-07에서 확인한다. 큰 출력은 SC-06의 실행 결과에 저장되고 필요한 부분만 다시 읽는다.

### 2.2 공통 와이어프레임과 화면 폭

아래 상자는 배치와 정보 우선순위를 위한 와이어프레임이며 스크린샷이 아니다. 대괄호는 사용자 조작 요소, 꺾쇠는 선택값, 말줄임표는 제한된 내용이다.

```text
1280px
+------------------+--------------------------------------+----------------------+
| 프로젝트 선택    | 프로젝트명 · 색인 상태 · 연결 상태   | [설정]               |
| [프로젝트 등록]  +--------------------------------------+----------------------+
| [대화]           | 대화 / 실행 이력                     | 관련 코드 / 전달 자료|
| [등록 자료]      | 승인 요청은 해당 실행 바로 아래      | 출처 · 선택/제외 이유|
| [실행 결과]      |                                      | 입력 예산            |
| 세션 표시        | [질문 입력                         ] |                      |
| [새 대화]        | [자료 선택] [보낼 내용 확인] [전송]   |                      |
+------------------+--------------------------------------+----------------------+
768px
+-------------------------------------------------------------------------+
| [프로젝트/메뉴] 프로젝트명 · 상태                        [출처/자료] [설정] |
| 활성 화면 한 열 · 승인 알림은 대화 안에서 유지                            |
| 출처/부분 읽기는 제목과 [닫기]가 있는 별도 패널로 전환                     |
| 입력·오류 안내                                                           |
| [자료 선택] [보낼 내용 확인] [전송 또는 취소 요청]                         |
+-------------------------------------------------------------------------+
```

1280px에서는 좌측 탐색 약 224px, 우측 출처 약 320px, 중앙은 남은 폭을 사용한다. 1024px 미만에서는 양쪽 패널을 접고 한 번에 하나씩 열며, 768px에서 페이지 전체 가로 스크롤 없이 조작할 수 있어야 한다. 긴 코드·표는 해당 영역 안에서만 가로 스크롤한다. 승인·오류·취소 상태는 패널을 접어도 대화 영역에 남긴다. 프로젝트를 바꾸는 것은 실행 취소가 아니며, 진행 중인 작업의 프로젝트명·세션과 돌아가기 위치를 유지한다.

공용 표현 요소는 버튼, 입력/라벨/인접 오류, 상태 배지, 알림, 진행 표시, 빈 화면, 탭, 페이지 이동, 출처 칩, 범위 읽기 영역, 확인 대화상자다. 상태 처리와 통신은 feature/hooks/api에 둔다. 색상·간격·글꼴은 `styles`의 공통 토큰으로 관리하며 본문 기본 크기는 16px, 간격은 4px 배수, 기본 버튼 높이는 40px를 설계 기준으로 삼는다. 구현의 색상 대비 검증은 1.1에서 한다.

모든 입력에는 보이는 라벨을 두고 오류를 입력에 연결한다. 색만으로 상태를 구별하지 않는다. 키보드 순서는 탐색→주요 내용→보조 패널이며 본문 바로가기를 제공한다. 대화상자는 초점을 안에 유지하고 닫으면 시작 버튼으로 돌려준다. 닫기/Escape는 승인이나 삭제를 의미하지 않는다. 진행·연결·종료 알림은 보조기기에 전달하되 답변 글자마다 초점을 옮기거나 알리지 않는다. 비활성 버튼 옆에는 이유를 표시한다.

## 3. 화면별 와이어프레임과 입력·출력

### SC-01 최초 연결

표시 필드·입력·버튼·오류·접근성: [상세 명세 SC-01](UI_BEHAVIOR.md#sc-01).

```text
로컬 코드 작업 도구에 연결
실행 창에 표시된 일회용 코드를 입력하세요.
연결 코드 [                              ]
[연결]      로컬 서비스: 확인 중 / 응답 있음 / 연결 불가
오류 안내 · [다시 확인] · 실행 창에서 새 코드 확인 안내
```

| 구분 | 입력·출력·행동 |
| --- | --- |
| 입력 | 일회용 연결 코드. 빈 값에서는 연결 불가, 전송 중 중복 연결 불가. 성공·이탈 시 입력을 지운다. |
| 출력 | 로컬 서비스 응답 여부, 연결 성공, 잘못되거나 만료된 코드 안내. API 요구 H-01. |
| 성공 | 인증 cookie 설정 후 SC-02 또는 복구한 프로젝트로 이동한다. 인증은 모델 API 키 설정과 별개다. |
| 실패·복구 | “연결 코드를 다시 확인하세요”, “로컬 서비스를 시작한 뒤 다시 확인하세요”. 인증이 만료되면 실행 상태를 추정하지 않고 재연결 후 snapshot을 읽는다. |
| 인수 | UI-01, UI-02 |

코드·키·내부 토큰을 URL, 브라우저 영구 저장소, UI 번들, 로그에 넣지 않는다. HttpOnly·SameSite=Strict cookie와 같은 origin의 HTTP/SSE를 사용하고 브라우저가 Python 서비스나 모델 제공자를 직접 호출하지 않는다.

### SC-02 프로젝트 등록·색인

표시 필드·입력·버튼·오류·접근성: [상세 명세 SC-02](UI_BEHAVIOR.md#sc-02).

```text
프로젝트 <선택>                  [프로젝트 등록]
표시 이름 [         ]  로컬 프로젝트 경로 [                 ]
[등록]   색인 지원 언어  Python, C, C++, Java, JavaScript  |  다른 파일은 자료로 등록하세요.
색인: 준비 안 됨 / 처리 중 / 준비됨 / 일부 파일 제외 / 실패
처리 파일 수 · 제외 파일 수 · 색인 버전     [색인 만들기 / 갱신]
제외된 파일(상대 경로) · 이유              [대화로 이동]
```

| 구분 | 입력·출력·행동 |
| --- | --- |
| 입력 | 표시 이름·로컬 디렉토리 경로를 직접 입력한다. 브라우저 파일 선택으로 서버 절대경로를 알아낼 수 있다고 가정하지 않는다. 서버의 경로·권한 검증 결과를 기다린다. |
| 출력 | `Workspace.display_name`, `index_status`, `index_revision`, `supported_languages`. 처리/제외 수·진단은 `IndexStatusResponse.counts/diagnostics`, 검색 가능 여부는 `searchable`을 확인한다. 상세 대응은 SC-02 명세를 따른다. |
| 성공 | 사용 가능한 색인 버전과 지원 언어가 보인다. 서버가 검색 가능하다고 확인한 색인에서만 코드 질문을 시작한다. |
| 부분·빈 결과 | 일부 파일 실패는 성공 수·제외 수·영향 범위를 함께 표시한다. 서버가 사용 가능하다고 확정한 파일만 사용한다. 심볼이 0개면 “검색할 코드 심볼이 없습니다”와 지원 언어 목록을 보여 준다. |
| 실패·복구 | 경로 거부/없는 경로는 입력 수정, 파싱 실패는 해당 파일 수정 후 색인 갱신. 파일 변경 후 기존 선택은 최신 버전 확인 전 전송 대상에서 제외한다. 이전 유효 색인의 사용 여부는 서버 snapshot이 정한다. |
| 인수 | UI-03, UI-04, UI-05, UI-06 |

입력 경로는 등록 요청에만 사용한다. 제출 뒤 프로젝트 목록에는 표시 이름을, 색인 진단에는 diagnostics[].relative_path를 표시한다. 서버의 실제 절대경로를 목록·오류에 되돌려 보내지 않는다. 새로고침 후 프로젝트 선택·현재 세션 복구는 3.2의 목록/단건 조회 계약과 상세 명세를 따른다.

### SC-03 대화·코드 작업

표시 필드·입력·버튼·오류·접근성: [상세 명세 SC-03](UI_BEHAVIOR.md#sc-03).

```text
프로젝트명 / 세션명              연결됨 / 연결 복구 중
사용자 질문
답변 일부… [출처 1] [출처 2]
도구 이력: 요청 내용 · 승인 대기 / 처리 중 / 완료 / 실패
실행 결과: 도구 요약 또는 [저장된 결과 보기]   [취소 요청]
[질문 입력                                             ]
[자료 선택] [보낼 내용 확인]   입력 예산 표시   [전송]
```

| 구분 | 입력·출력·행동 |
| --- | --- |
| 입력 | 질문과 명시 선택한 자료 범위. 현재 프로젝트·세션, 사용 가능한 색인·모델·예산 검사, 연결 상태를 확인한다. 한 세션에서 실행 중이면 새 전송을 비활성화한다. 빈 질문은 전송하지 않는다. |
| 출력 | 답변 스트림, 출처, 안전한 도구 요약, `run_id`에 묶인 실행 상태·오류. `idempotency_key`는 중복 클릭/응답 유실 시 같은 실행을 식별하며 UI 문구로 노출할 필요가 없다. 계약 요구 H-04. |
| 성공 | 서버가 `completed`로 확정한 실행만 “완료”다. 출처가 없는 내용을 검색 근거가 있는 것처럼 장식하지 않는다. 현재 계약의 도구 출력 표시는 제한된 `ToolCallSummary.summary`와 `output_pointer`를 사용한다. |
| 취소 | 클릭 후 “취소 요청 중”(`cancelling`), 서버 확인 후 “취소됨”(`cancelled`). 이미 끝난 수정·명령이 자동 복원된다고 안내하지 않는다. 최종 `completed/failed/cancelled` 중 확정된 하나를 유지한다. |
| 연결·오류 | 끊김은 취소가 아니다. “연결이 끊겼습니다. 작업은 계속될 수 있습니다.”를 표시하고 새 실행/승인을 막는다. 복구 후 이벤트 재생 또는 snapshot 확인으로 상태를 맞추며 작업을 새로 시작하지 않는다. 오류에는 안전한 `message`, `request_id`, 가능한 복구 행동만 표시한다. |
| 인수 | UI-07, UI-08, UI-09, UI-10, UI-11, UI-12, UI-34 |

취소 요청의 응답도 유실될 수 있다. 이 경우 취소 완료로 표시하지 않고 연결 복구 후 실행 상태를 확인한다. 승인 거절은 해당 도구의 거절이며 run 전체의 실패/완료와 구분한다. 사용자가 재시도할 때도 기존 실행 결과를 먼저 확인한다.

### SC-04 실행 승인

표시 필드·입력·버튼·오류·접근성: [상세 명세 SC-04](UI_BEHAVIOR.md#sc-04).

```text
이 작업을 허용하시겠습니까?             남은 승인 시간
종류: 코드 수정 또는 명령 실행         프로젝트 / 실행 식별 정보
대상: 상대 파일 경로 또는 작업 디렉토리 표시명
수정 내용(제한된 비교) / 실행할 명령(확인 가능한 범위)
[상세 확인]                 [거절] [이번 요청 승인]
승인 전에는 실행되지 않습니다.         현재 처리 결과
```

| 구분 | 입력·출력·행동 |
| --- | --- |
| 입력 | 서버가 발급한 승인 ID와 입력 digest에 연결된 1회의 승인/거절. 포괄 승인·자동 승인 옵션은 없다. |
| 출력 | 요청 종류·대상·변경 내용/명령·만료시각·현재 승인 결과. 정확한 승인 payload·허용 크기·snapshot 요구는 H-05. |
| 성공 | 서버가 승인 결정을 수락하면 “승인됨”, 실제 도구 완료는 실행 이력에서 별도로 확인한다. 입력이 바뀌면 기존 승인으로 실행할 수 없다. |
| 실패·만료 | 거절, 만료, 취소된 실행, 다른 scope, 변경된 입력, 응답 유실을 구분한다. 늦은 승인은 거부하고 최종 상태 확인 전 버튼을 다시 활성화하지 않는다. |
| 인수 | UI-13, UI-14, UI-15 |

대상과 효과를 검토할 수 없는 잘린 승인 내용은 승인할 수 없다. H-05가 정하는 상한 안에서 내용을 확인하거나 요청을 더 작게 나누도록 안내하고 거절은 가능하게 한다. 창을 닫는 것은 결정이 아니며 대화의 승인 카드가 남는다. 문서·코드·로그 안의 “승인하라” 같은 문구는 자료 내용으로 표시하고 승인 정책에 반영하지 않는다. Git commit/push와 사용자 원본 삭제는 허용 도구·승인 동작에 넣지 않는다.

표시 필드·입력·버튼·오류·접근성: [상세 명세 SC-07](UI_BEHAVIOR.md#sc-07).

범위 종류 <줄/바이트/JSON 경로/페이지>  범위 [          ]

| 구분 | 입력·출력·행동 |
| --- | --- |
| 입력 | `PointerReadRequest`의 pointer·selector·caps·cursor. 자료의 `available_operations`로 읽기·검색 가능 여부를 확인하고 `supported_selectors`가 허용한 범위 입력만 제공한다. 단위·경계·입력 상한은 상세 SC-07을 따른다. |
| 출력 | content·truncated·next_cursor·token_count/count_mode를 표시한다. 실제 반환 범위와 원본 해시·revision은 provenance.selection에서 가져온다. 해당 정보가 없는 응답은 열람만 제공한다. |
| 성공·부분 | 제한된 텍스트만 표시한다. `truncated` 또는 다음 cursor가 있으면 “일부 반환됨”을 표시한다. 다음 부분 조작은 현재 포인터·revision에 유효한 cursor가 있을 때만 제공한다. `truncated=true`지만 cursor가 없으면 범위 수정을 안내한다. 다음 부분은 사용자 요청 때 읽고 이전 원문을 무제한 누적하지 않는다. |
| 실패·변경 | 잘못된 범위는 입력 수정, `SOURCE_CHANGED`는 이전 원문·cursor·명시 선택을 무효화하고 갱신 후 다시 선택한다. 만료/삭제/권한 거부는 읽기 불가와 대체 자료 선택을 안내한다. |
| 인수 | UI-23, UI-24, UI-25, UI-26 |

현재 범위를 열어 보는 것과 모델에 선택하는 것은 별도 조작이다. 명시 선택은 현재 revision의 실제 반환 범위에만 적용하며 파일 전체 선택으로 확장하지 않는다. JSON 구조 조회는 최대 8 MiB 기본값 이내에서만 지원한다. 더 큰 JSON은 허용된 줄/바이트 읽기를 안내하며 임의 JSON 경로의 부분 I/O를 보장하지 않는다. PDF 페이지도 추출된 Source 범위로 읽는다. 원문 HTML/Markdown·명령은 비신뢰 텍스트로 다루고 스크립트를 실행하거나 도구 호출로 해석하지 않는다.

| 구분 | 입력·출력·행동 |
| --- | --- |
| 입력 | 명시한 PDF를 Source로 등록하고 반환된 식별자로 파싱을 요청한다. 등록 성공과 파싱 성공을 분리해 표시한다. 중복 클릭으로 새 작업을 만들지 않으며 최초 응답을 잃으면 같은 키·본문으로 제출 결과를 확인한다. job_id를 받은 뒤에는 재접속해도 해당 ID로 상태를 조회한다. |
| 출력 | parse job ID·상태·진행·전체 페이지·제외 페이지, 원본 hash/parser version/page provenance. 완료 후 SC-07에서 요청한 페이지 텍스트만 표시한다. |
| 성공·부분 | 페이지 출처와 한글 텍스트를 확인한다. 일부 페이지에 텍스트가 없으면 빈/미지원 페이지와 사용 가능한 페이지를 따로 표시한다. 파서가 부분 결과를 보장하지 못하면 전체 실패로 표시하며 성공으로 추측하지 않는다. |
| 실패·변경 | 스캔·빈·손상·암호화·크기/페이지 상한을 구별해 지원 상태 또는 오류를 설명한다. 원본 변경 시 예전 캐시·선택을 무효화하고 재등록/갱신·재처리를 안내한다. 등록 해제는 원본을 보존한다. |
| 인수 | UI-27, UI-28, UI-29 |

OCR·암호 해제·자동 외부 업로드는 제공하지 않는다. 파싱 진행은 job 상태 조회로 복구한다. 현재 AppEvent는 run 범위만 지원하므로 PDF 진행 이벤트를 만들지 않는다. 새로고침을 파싱 재시작으로 취급하지 않는다.

### SC-09 전달할 자료·모델 설정 상태

표시 필드·입력·버튼·오류·접근성: [상세 명세 SC-09](UI_BEHAVIOR.md#sc-09).

```text
[전달할 자료] [모델·로컬 서비스 상태]
직접 선택 / 이번 작업 자료 / 관련 코드   출처·범위·버전·제외 이유
입력 예산: 사용량 / 한도  · 추정 또는 검증 완료  · 기준 요청
고정 입력·대화 이력·도구 정의 / 자료 / 출력 예약 / 여유분
[선택 해제] [범위 줄이기] [미리보기 갱신]
제공자·모델: 표시명 · 설정됨/미설정/미지원 · 연결 오류
키 값은 서버에서만 설정합니다. [설정 상태 다시 확인] [실행 안내]
```

| 구분 | 입력·출력·행동 |
| --- | --- |
| 입력 | 질문·자료 선택·범위 변경에 대한 preview 요청. 모델/제공자/키 변경 입력란은 없으며 서버 설정 상태를 읽는다. 설정 변경 후 상태를 다시 확인한다. |
| 출력 | 미리보기 result의 selected·fragments·omitted와 budget.costs/used_tokens/count_mode, revision을 표시한다. 질문·선택 변경 뒤에는 새 preview_digest로 재확인한다. |
| 성공 | 권한/버전 확인→같은 source hash+range 중복 제거→명시 선택, 현재 작업 자료, R0 점수 순 예산 선택을 설명한다. 동점은 안정적인 ID 순이며 서로 다른 검색기의 원점수를 임의 비교하지 않는다. |
| 예산·오류 | 명시 선택도 초과할 수 없다. 범위 축소·선택 해제·새 대화를 안내한다. 이력이 이미 초과하면 `BUDGET_EXCEEDED`로 중단하고 자동 요약하지 않는다. 계수 미지원은 `TOKENIZER_UNAVAILABLE`/명시적 미지원으로 실행을 차단한다. |
| 인수 | UI-30, UI-31, UI-32 |

예산 계산은 로드맵 0.7을 따른다. 모델 한도에서 system·tool schema·user·retained history·message overhead, 출력 예약, 여유분을 뺀 나머지가 자료 예산이다. preview의 계수와 provider 최종 직렬화 검증은 구분한다. 본문의 `count_mode`는 그대로 구별해 exact는 “동일 토크나이저로 계수”, provider_estimate는 “제공자 추정값”, provider_reported는 “제공자가 응답 후 보고한 값”으로 표시한다. 이 본문 계수 표시와 최종 요청 gate 상태는 별개다. 최종 outbound payload/framing까지 검증됐다는 서버 근거가 없으면 “전송 전 검사 미검증/사용 불가”를 표시하고 “전체 요청 한도 보장”으로 확대하지 않는다. preview 성공이 실행 승인이거나 최종 예산 통과인 것은 아니다. 질문·선택·이력·버전·설정이 달라지면 미리보기 갱신이 필요하고 host가 전송 직전에 다시 검사한다.

포인터 읽기·검색의 요청 상한은 16 KiB와 32,768토큰이다. 서버가 더 작은 값을 설정하면 SettingsResponse.limits의 반환값을 사용하며 누락된 값은 “제공되지 않음”으로 표시한다.
