## 1. 왜 다시 BLOCKED인가

[`3.6-prerequisite-defects.md`](3.6-prerequisite-defects.md)는 D1~D8과 N1~N3을 "수복 완료"로 적었다. 하지만 현재 checkout(`d598c0b1`)에서 같은 결함 범주가 아래처럼 재현된다. 근거 시험 `test_handoff_reproduction_d1_d8.py`는 `obj`/xref가 없는 가짜 바이트열과 가짜 registry만 사용한다. 그래서 실제 PDF 구조나 실제 registry 경로를 검증하지 않는다.

로드맵에서 4.3~4.9의 `[x]`는 김민지 커밋 `94ec5d4f`(1.4 UI 병합)에서 바뀌었다. 이 커밋이 2026-11-09 재검토 판정을 되돌렸다. 각 작업 기록 `docs/progress/tasks/4.4|4.6|4.8|4.9.md`의 첫 판정은 여전히 **BLOCKED**다. 3.6은 다른 담당자의 체크를 수정하지 않는다. 원래 담당자가 체크와 기록을 일치시켜야 한다.

## 3. 재현 코드 요약

```python
# P1/P2: 정상 PDF 생성 — 각 객체 offset으로 xref를 만들고 trailer /Root 1 0 R
objs = {1: b"<< /Type /Catalog /Pages 2 0 R >>",
        2: b"<< /Type /Pages /Kids [3 0 R] /Count 1 >>",
        3: b"<< /Type /Page /Parent 2 0 R /Contents 4 0 R >>",
        4: flate_stream(b"BT /F1 12 Tf (FLATE_PAGE_ONE) Tj ET")}
PdfParser().parse_pages(build_pdf(objs, root=1))       # P1: text == ""
# P2: Kids [5 0 R 3 0 R], 3→"SECOND_PAGE", 5→"FIRST_PAGE"; target_pages=[1] → "SECOND_PAGE"

# P5
uri = "securecode://source/ws1/abc?v=1"
ContextSelectorPolicy().select([
    {"candidate_id": "a", "ref": {"uri": uri, "range": {"start_line": 1, "end_line": 10}}, "score": 0.9, "estimated_tokens": 10},
    {"candidate_id": "b", "ref": {"uri": uri, "range": {"start_line": 500, "end_line": 510}}, "score": 0.8, "estimated_tokens": 10},
], max_tokens=1000)                                    # omitted == [DUPLICATE]

TestClient(securecode_context.main.app).post("/v1/context/select", json={"candidates": [], "max_tokens": 10})  # 200
```

전체 스크립트는 3.6 작업 중 임시 디렉토리에서 실행했다. 제품 루트에 임시 파일을 남기지 않기 위해 저장소에는 넣지 않았다. 위 표만으로 각 항목을 실패하는 회귀 시험으로 옮길 수 있다. 정상 PDF 생성은 xref·`/Length`·`zlib.compress`만 있으면 된다.

## 4. 재개 조건(3.6 쪽에서 확인할 것)

1. 4.3 → 4.4, 4.5 → 4.6, 4.7 → 4.8, 4.9가 각 기록에서 BLOCKED를 해제하고, P1~P12가 해당 담당 시험으로 고정되어 통과한다.
2. 4.8이 `ModelRequestGate` 포트 구현을 export하고, 3.6이 `main.ts`의 `gate: null`을 교체할 수 있다.
3. Python 서비스의 context/source/pdf 포트가 `app/factory.py`의 인증 라우터 아래에 있고, 미인증 `securecode_context.main`이 없다.
4. 4.9가 실제 PDF 파서를 쓴다. 의존성 추가는 루트 lock 소유자(박준형)에게 `docs/handoffs/`로 요청하면 3.6에서 반영한다. 다중 페이지·압축·한글 ToUnicode·손상·암호화 fixture가 필요하다.
5. live smoke용 provider 설정(로컬 qwen-2.5 엔드포인트 등)이 서버 환경에 준비된다. 현재 checkout에는 `.env`·`SECURECODE_*` provider 설정이 없고, `build_token_counter`는 `anthropic`만 지원한다.
