## 2. 1.1/1.4 (UI)

- Vite 설정에서 `scripts/dev/viteProxy.ts`의 `createViteApiProxy()`를 `server.proxy`로 쓴다. UI 코드는 `/api/v1/...` 상대 경로만 호출한다. cookie는 JS에서 읽지 않는다.
- 첫 화면은 launch code 입력이다. 코드를 받으면 `POST /api/v1/auth/bootstrap {code}`를 호출한다. 실패 코드는 다음과 같다.
  - `BOOTSTRAP_CODE_INVALID`: 이미 쓴 코드도 포함한다.
  - `BOOTSTRAP_CODE_EXPIRED`
  - `RATE_LIMITED`: 20회 실패 뒤
  - 이후 `UNAUTHENTICATED`(401)를 받으면 다시 bootstrap 화면을 보인다.
- **현재 운영 host는 4.4/4.8 hook이 등록되지 않아 세션 생성이 `PROTECTION_UNAVAILABLE`(503)이다.** `GET /settings`의 `protections`에서 `runtime_pointer_hook`, `model_request_gate`가 `ready:false`로 보인다. 화면은 이 상태를 표시해야 하며 성공으로 꾸미지 않는다.
- 실제 응답 예시는 시험이 계약으로 검증한다(`apps/host/tests/integration/sdkRuns.test.ts`). 순서는 다음과 같다.
  1. `run.status_changed` `queued → running`
  2. 필요하면 `run.approval_requested`와 `awaiting_approval`
  3. `run.tool_call_updated`
  4. `run.output_delta`
  5. 종료 `run.status_changed{terminal}`
- 승인 결정은 `pending_approvals[].input_digest`를 그대로 보낸다. 결정 오류는 다음과 같다.
  - `APPROVAL_DIGEST_MISMATCH`
  - `APPROVAL_EXPIRED`
  - `APPROVAL_ALREADY_DECIDED`: 취소·늦은 결정 포함
  - `VALIDATION_FAILED`: `reviewable=false`인데 approve를 보낸 경우
- SSE는 `GET /api/v1/runs/:id/events`다. `Last-Event-ID` 재연결을 지원한다. `stream.replay_unavailable`을 받으면 스트림이 닫히므로 snapshot을 다시 읽고 `replay.last_sequence`부터 재구독한다. 15초마다 `: keep-alive`가 온다.

## 3. 4.4 (ToolResultTransformer)

- 포트: `apps/host/src/cline/adapter/ports.ts`의 `ToolResultTransformer.transform(input, signal)`
- 어댑터: `apps/host/src/cline/adapter/toolResultHook.ts`가 afterTool에서 호출한다. 동작은 다음과 같다.
  - `SECURECODE_HOOK_TIMEOUT_MS` 안에 끝나지 않거나 throw하면 run은 `failed`(`SERVICE_UNAVAILABLE`)가 된다. 다음 모델 요청은 가지 않는다.
  - `kind:"pointer"`이면 `run.pointer_created`와 `tool_call.output_pointer`가 만들어진다.
- 연결 위치: `apps/host/src/app/main.ts`의 `transformer: null`을 4.4 구현으로 바꾼다. 바꾸면 `runtime_pointer_hook` 보호가 ready가 된다.
- 시험 fixture: `apps/host/tests/support/fixtureHooks.ts`의 `FixtureTransformer`. 4096바이트 이상이면 pointer, `mode="fail"|"hang"`을 지원한다. **fixture이며 정책 구현이 아니다.**

## 4. 4.8 (ModelRequestGate)

- 포트: `ModelRequestGate.check({providerId, modelId, body, maxOutputTokens}, signal)`. `body`는 SDK가 직렬화한 실제 provider HTTP 본문이다.
- 어댑터: `apps/host/src/cline/adapter/requestGateFetch.ts`가 `ClineCoreOptions.fetch`에서 호출한다. 처리는 다음과 같다.
  - 거부: 요청을 보내지 않고 run을 `failed`(gate가 준 code)로 끝낸다.
  - throw: `TOKENIZER_UNAVAILABLE`로 끝낸다.
  - 본문의 `tools`에 허용 목록 밖 도구가 있으면 gate를 부르기 전에 `PROTECTION_UNAVAILABLE`로 막는다.
- 연결 위치: `main.ts`의 `gate: null`. 연결하면 `model_request_gate`가 ready가 된다. settings의 `final_request_gate`는 4.8이 정책을 검증하기 전까지 `not_verified`다.
- 시험 fixture: `FixtureGate`(`allow|block|throw`). 반환 숫자는 bytes이며 토큰 수가 아니다.
