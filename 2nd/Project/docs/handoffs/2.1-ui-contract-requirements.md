> 발신 역할: 김찬우 2.1 · 수신 역할: 박준형 3.2, 임우형 4.2, 김민지 1.1 이후

## 1. 인계의 효력과 소유권

로드맵 0.6은 신규 애플리케이션 계약 **초안**이다. 현재 확정 schema·생성 타입·fixture는 없다. 아래 H 번호는 화면이 필요로 하는 정보이며 실제 SDK API나 AppEvent의 `type` 이름이 아니다. JSON 필드는 snake_case, UI 매핑은 단일 mapper, 소비자는 3.2/4.2가 확정한 스키마/생성 타입을 사용한다. 상태 enum·추가 DTO를 이 문서에서 임의 구현하지 않는다.

초기 계약은 `schema_version: "1"`을 기준으로 3.2/4.2가 확정한다. 이미 배포된 계약을 변경하는 작업이 아니므로 이 인계에서 version을 올리지 않는다. 확정 시 각 H 번호의 수용 방식·최종 필드·fixture ID·제한을 계약 문서에 연결하고, 이후 호환성 변경은 새 version·영향 파일·담당 작업을 별도 기록한다.

## 3. 이벤트·snapshot 요구

`AppEvent`의 공통 필드는 로드맵대로 `schema_version`, `event_id`, 단조 증가 `sequence`, `workspace_id`, `session_id`, `run_id`, `type`, `timestamp`, `payload`다. 아래는 전달해야 할 **사실의 목록**이며 wire `type` 문자열을 선점하지 않는다. SDK 이벤트를 그대로 UI에 전달하지 않는다.

| 전달할 사실 | 소비 화면·계약 | 필요한 내용·복구 경계 |
| --- | --- | --- |
| 실행 시작/진행·답변 조각·도구 상태·최종 결과 | SC-03, H-04 | run scope, 중복 식별, 정렬 기준, 안전한 답변·출처·도구 요약. `completed/failed/cancelled` 중 확정된 하나는 늦은 이벤트로 되돌리지 않음. |
| 승인 요청/결정·만료·취소 | SC-04, H-05 | 승인 ID·digest·만료·표시 가능한 내용·최종 결정. 연결 복구 시 대기/처리된 승인 snapshot과 일치. |
| 실행 결과 저장/삭제/만료 | SC-03, SC-06, H-07 | 제한 PointerDescriptor 또는 변경 사실만 전달. 전체 도구 원문 없음. 이벤트 없이 변경됐을 때도 목록/읽기 응답으로 감지 가능. |
| 컨텍스트 선택·제외·예산 차단 | SC-05, SC-09, H-06/H-09 | 원문 대량 재전송 없이 제한된 출처·이유·계수 결과. preview와 실제 run 결과의 차이를 식별. |
| 색인 진행·완료·부분 실패·변경 | SC-02, H-03 | 해당 workspace/revision의 GET 상태가 기준. run 전 작업이므로 run SSE가 반드시 존재한다고 가정하지 않음. 별도 알림이 필요하면 3.2가 scope를 설계. |
| PDF 파싱 진행·완료·실패 | SC-08, H-08 | job 상태 GET이 기준. job을 식별하는 이벤트는 보조 수단. run 없이 시작된 job에 임의 run ID를 만들어 연결하지 않음. |
| 서비스·인증·모델 설정 상태 | SC-01, SC-09, H-01/H-10 | health/settings와 인증 응답 기준. 아직 없는 전역 이벤트 스트림을 UI가 요구하지 않음. |

SSE는 같은 origin cookie를 사용하고 `Last-Event-ID`로 재생한다. 재생 범위를 넘었음을 감지하는 응답과 `GET /runs/:id` snapshot의 필수 필드·보존 범위를 3.2가 정의한다. `sequence`의 증가 범위와 이벤트/답변 조각을 안전하게 합치는 기준도 명시해야 한다. UI가 sequence를 임의 전역 번호로 해석하면 안 된다.

연결 단절 시 새 실행/승인을 잠그고 기존 실행은 계속될 수 있음을 알린다. 서버 확인 없는 취소 완료, 응답 재생에 따른 명령/승인 재실행, 이전 workspace/session/run 응답의 현재 화면 덮어쓰기는 허용하지 않는다. 기능별 상태 관리·자동 행동 시험은 김민지 1.3의 책임이다.

## 4. 확정할 fixture와 공통 오류

공통 `ApiError.code/message/retryable/request_id/details`의 민감정보 제거와 UI 복구 대응을 함께 확정한다. 로드맵의 필수 오류 16종은 [화면 설계의 오류 대응](../ui/SCREEN_SPEC.md)에 모두 연결돼 있다. HTTP 상태와 추가 인증/승인/용량 오류의 wire 이름은 3.2/4.2, 최종 표시 문구는 2.2가 정한다.

| fixture 묶음 | 필수 사례 | 연결 시나리오 |
| --- | --- | --- |
| 인증/프로젝트/색인 | 코드 만료·서비스 중지·경로 거부·진행·0개·부분 실패·색인 버전 변경 | UI-01, UI-02, UI-03, UI-04, UI-05, UI-06 |
| 실행/승인/이벤트 | 중복 생성·응답 유실·승인/거절·만료·입력 변경·취소 경합·중복/역순·replay 초과·scope 불일치·보호 기능 미준비 | UI-07, UI-08, UI-10, UI-11, UI-12, UI-13, UI-14, UI-15 |
| 심볼/포인터/부분 읽기 | 무결과·해결 불가 참조·상한·pagination·UTF-8·만료/삭제·다른 세션·변경 cursor·등록 해제 원본 보존 | UI-09, UI-16, UI-17, UI-18, UI-19, UI-20, UI-21, UI-22, UI-23, UI-24, UI-25, UI-26 |
| PDF | 한글 페이지·job 복구·부분 결과·스캔/빈/손상/암호화/크기/페이지 초과·원본/parser 변경 | UI-27, UI-28, UI-29 |
| 예산/설정/저장 | 중복 제거·우선순위·이력만 초과·미지원 계수·추정/검증·키 미노출·큰 로그 저장 실패/timeout | UI-30, UI-31, UI-32, UI-34 |

UI-33은 모든 묶음의 표현·키보드·두 화면 폭 검증에 적용한다. 초기 fixture도 성공 payload만 만들지 말고 각 실패·복구 사례를 포함한다. 서버가 제공하지 않은 값은 UI가 성공 상태나 정확한 토큰 수로 만들어 채우지 않는다.

루트 패키지/lockfile/공통 계약은 박준형, 포인터·Context 세부 계약은 임우형, 화면 상태·사용자 동작 코드는 김민지가 수정한다. 김찬우는 설계·문서·검토를 맡고 상태 전이표·reducer·machine·실행 타입을 산출물로 요구하지 않는다. UI 구현 중 계약 변경이 필요하면 H 번호와 영향 시나리오를 포함해 소유자에게 인계한다.
