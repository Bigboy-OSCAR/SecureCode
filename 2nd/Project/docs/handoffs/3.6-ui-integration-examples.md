# 3.6 UI 연동 예제 (2026-11-10)

host 공개 API(`/api/v1`)에 3.6이 연결한 경로의 실제 요청·응답 모양이다. 모든 응답은 `@securecode/contracts`의 스키마로 검증된다. 예제 값은 `apps/host/tests/integration/publicContextRoutes.test.ts`·`integratedContextSdk.test.ts`에서 실제로 오간 모양을 줄인 것이다. 인증·Origin·쿠키는 3.5와 같다.

## 1. 작업 공간 색인 (R0)

```http
POST /api/v1/workspaces/ws_…/index      {"idempotency_key": "index-0001"}
→ 202 IndexStatusResponse  {"index_status": "indexing", "index_revision": null, …}
GET  /api/v1/workspaces/ws_…/index
→ 200 IndexStatusResponse  {"index_status": "ready" | "partial", "index_revision": 1, "searchable": true, …}
```

- 상태는 GET으로 다시 확인한다. SSE는 없다.
- `partial`은 검색할 수 있고 파일별 진단이 있다는 뜻이다.
- 색인 전에도 run은 만들 수 있다. 이때 R0 후보는 없다.

## 2. Source 등록·읽기·검색·목록·해제

```http
POST /api/v1/workspaces/ws_…/sources
{"schema_version":"1","idempotency_key":"register-app-1","operation":"register",
 "target":{"location":"workspace","kind":"file","path":"app.py"}}
→ 200 SourceMutationResult {"items":[{"pointer":"securecode://source/ws_…/src_…?v=1", …}]}

POST /api/v1/pointers/read
{"schema_version":"1","pointer":"securecode://source/…?v=1","selector":{"type":"line","start":2,"end":2},"max_bytes":4096}
→ 200 PointerReadResult {"content":"…","provenance":{"selection":{"revision":1,"content_sha256":"…","range":{"type":"byte","start":40,"end":93}}},"truncated":false,…}

POST /api/v1/pointers/search   {"schema_version":"1","pointer":"…","query":"DISCOUNT"}  → 200 PointerSearchResult
GET  /api/v1/workspaces/ws_…/pointers?kind=source                                      → 200 PointerListResult
GET  /api/v1/workspaces/ws_…/pointers?kind=runtime&session_id=ses_…                    → 200 PointerListResult
DELETE /api/v1/pointers {"schema_version":"1","idempotency_key":"…","kind":"source","pointer":"…","workspace_id":"ws_…"}
→ 200 PointerDeleteResult {"effect":"unregistered",…}
```

- Runtime Pointer(`securecode://runtime/ws_…/ses_…/…`)도 같은 read/search 경로를 쓴다. host가 URI의 세션이 그 작업 공간 소속인지 확인한다.
- 모든 읽기는 16 KiB·토큰 상한 안이다. 더 읽으려면 `next_cursor`를 쓴다.

## 3. 컨텍스트 미리보기 → run

```http
POST /api/v1/context/preview {"operation":"search","input":{"workspace_id":"ws_…","query":"apply_discount","index_revision":1}}
→ 200 {"operation":"search","result":SymbolSearchResponse}          (원문 없음)
POST /api/v1/context/preview {"operation":"bundle","input":{"workspace_id":"ws_…","candidate_id":"cand_…","index_revision":1,"max_tokens":2000}}
→ 200 {"operation":"bundle","result":SymbolBundle}                  (상한 안 원문)
POST /api/v1/context/preview {"operation":"plan","input":{"workspace_id":"ws_…","session_id":"ses_…","index_revision":1,
      "prompt":"할인 계산은?","context_refs":[{"kind":"source","pointer":"…","selection":{…읽기 결과 그대로…}}]}}
→ 200 {"operation":"plan","result":ContextPreviewPlan}   preview_digest, selected/fragments/omitted, budget(costs, count_mode)

POST /api/v1/sessions/ses_…/runs {"prompt":"할인 계산은?","idempotency_key":"run-good-0001","context_refs":[…],"preview_digest":"…"}
→ 201 RunSnapshot
```

- run은 미리보기와 같은 입력으로 계획을 다시 만든다. fragment는 첫 사용자 메시지에 한 번만 들어간다. 형식은 `<securecode-context id="cand_…" source="…">…</securecode-context>`이다.
- 같은 세션의 다음 run은 이미 보인 범위를 다시 넣지 않는다.

**실패 예** (모델 호출 없음):

| 상황 | 응답 |
| --- | --- |
| `preview_digest`가 현재 계획과 다름 | 422 `VALIDATION_FAILED`, `details.reason="stale_preview"` → 미리보기를 다시 요청 |
| 명시 범위의 원본 해시가 다름 | 409 `SOURCE_CHANGED`, `details.reason="stale"` |
| 명시 범위가 예산이나 fragment 상한을 넘음 | 413 `BUDGET_EXCEEDED`, `details.reason="over_budget"\|"large_fragment"` |
| 다른 작업 공간·세션의 포인터 | 403 `FORBIDDEN` |
| context-service가 꺼짐 | 503 `SERVICE_UNAVAILABLE` |
| 최종 요청 계수 실패·창 초과 (run 중) | run `failed`, `terminal.reason_code` = `TOKENIZER_UNAVAILABLE` 또는 `BUDGET_EXCEEDED` |

## 4. PDF

```http
POST /api/v1/pdf/parse {"schema_version":"1","workspace_id":"ws_…","pointer":"securecode://source/…?v=1","idempotency_key":"parse-pdf-0001"}
→ 200 PdfJobStatus {"job_id":"pdf_…","state":"queued"|"running"|"ready",…}   (추출 본문 없음)
GET  /api/v1/pdf/jobs/pdf_…  → 200 PdfJobStatus {"state":"ready","page_count":3,"parser_version":"pdf-text-v1+pypdf-…",…}
POST /api/v1/pointers/read {"schema_version":"1","pointer":"…","selector":{"type":"pdf_page","start":2}}
→ 200 PointerReadResult (selection.range.type="pdf_page", page=2)
```

host를 다시 시작하면 job ID를 모른다(404). 이때는 parse를 다시 요청하면 된다. 캐시가 있으면 바로 `ready`다.

## 5. 실행 중 화면

| 이벤트·상태 | 뜻 |
| --- | --- |
| `tool_calls[].tool_name` | `read_file`, `search_file`, `code_search`, `code_read`, `list_files`, `run_command`, `write_file`, `runtime_read`, `runtime_search`, `pdf_parse`, `pdf_status`, `pdf_search`, `pdf_read_pages` 중 하나 |
| `tool_calls[].output_pointer` | 큰 출력이 Runtime Pointer로 저장됨. 2절 read/search로 부분 조회 |
| `pending_approvals[]` | `run_command`·`write_file` 승인 대기. 3.5 승인 경로 |
| `cancelling` → `cancelled` | `POST /runs/:id/cancel` |
