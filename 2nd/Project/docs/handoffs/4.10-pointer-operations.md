# 포인터·예산·PDF 운용 안내 (4.10 → 3.7·1.6)

- 작성: 2026-11-10, 박준형(4.x 담당, 팀 합의)
- 대상: 3.7(로컬 패키징·회귀 검사), 1.6(UI end-to-end)
- 근거 시험: [tests/integration/README.md](../../tests/integration/README.md)

## 1. 저장 위치

모든 서비스 데이터는 `SECURECODE_DATA_DIR`(기본: 작업 루트의 `.securecode`, git 제외) 아래에 있다. 사용자 원본 파일은 어디에도 복사해 두지 않는다. 예외는 PDF 파싱 중 작업 폴더의 임시 복사본으로, 파싱이 끝나면 지운다.

| 경로 | 내용 | 지워도 되나 |
| --- | --- | --- |
| `runtime/runtime.sqlite3`, `runtime/blobs/<ws>/<ses>/` | Runtime Pointer(도구 출력)의 행·청크 checksum·원문 | 서비스를 멈춘 뒤에만 지운다. 지우면 기존 포인터는 `NOT_FOUND`다 |
| `sources/registry.sqlite` | Source 등록(상대 경로·revision·원본 SHA-256·identity). 원문은 없음 | 지우면 재등록이 필요하다 |
| `derived/pdf-<키>/` | PDF 페이지 캐시(`manifest.json`, `pages/NNNN.txt`). 키 = 원본 SHA-256 + 파서 버전 | 지워도 된다. 다음 parse가 다시 만든다 |
| `pdf-work/` | 진행 중 파싱의 임시 폴더 | 서비스 시작 때 자동으로 비운다 |
| `symbols/<ws>/symbols/` | R0 색인 revision(`current.json`, `revisions/<n>.json`). 최근 2개 유지 | 지워도 된다. 다시 색인하면 된다 |
| `workspaces.json` | 작업 공간 ID → root (host가 등록) | host가 다음 호출 때 다시 등록한다 |
| `cline/` | SDK session store(대화 기록). 큰 원문은 포인터로 바뀐 상태로 저장됨 | 지우면 SDK 대화 기록이 사라진다 |
| `host/` | run·세션·작업 공간·idempotency 기록 | host가 쓰는 상태 |

## 2. 수명·용량·상한

| 항목 | 값 | 넘으면 |
| --- | --- | --- |
| Runtime 출력 TTL | 기본 24시간, 최대 7일 | 읽기는 `EXPIRED`. 서비스가 시작 때와 10분마다 파일을 지운다(4.10에서 연결) |
| Runtime 출력 1개 | 32 MiB (명령 출력은 32 MiB에서 잘림, descriptor에 표시) | `PAYLOAD_TOO_LARGE`, 실행기는 잘린 범위를 기록 |
| 세션 합계 | 128 MiB | `QUOTA_EXCEEDED`. 도구 결과는 원문 대신 오류다 |
| 세션 종료 | 세션 닫기 → 그 세션 출력 삭제(`session_cleared`) | — |
| 도구 결과 원문 유지 | 4 KiB 미만만 그대로. 이상은 포인터 + 512 B 미리보기 | — |
| 부분 읽기 | 한 번 16 KiB, 32,768 토큰, 남은 요청 창 이하 | 다음 cursor |
| 검색 | 일치 최대 50(도구)·100(API), 요청당 scan 8 MiB·2초 | `truncated` + cursor |
| 목록 | 한 페이지 최대 100 | cursor |
| Source 원본 | 텍스트 256 MiB, PDF 50 MiB. JSON 구조 조회는 8 MiB 이하 | `PAYLOAD_TOO_LARGE`(json_structured_limit), 줄·바이트 읽기는 가능 |
| PDF | 500쪽, 파싱 60초, 페이지 텍스트 1 MiB | `unsupported`/`failed` 상태 |
| 모델 요청 | `SECURECODE_MODEL_CONTEXT_LIMIT`(로컬 qwen 32,768) − 출력 예약 − 마진 | 보내지 않고 `BUDGET_EXCEEDED` |

## 3. 지원 형식

- **텍스트**: UTF-8 텍스트, Markdown(절 selector), JSON(JSON Pointer, 8 MiB 이하).
- **PDF**: 텍스트 PDF만(pypdf, ToUnicode 글꼴). 지원하지 않는 것:
  - 스캔 PDF(OCR)
  - 암호화 PDF
  - 500쪽 초과, 50 MiB 초과
  - 손상 파일
- **코드 검색(R0)**: Python·C·C++·Java·JavaScript.
- **바이너리 파일**: 등록을 거절한다.

## 4. 캐시 재생성과 원본 보존

- **Source가 바뀜**: 읽기는 `SOURCE_CHANGED`, PDF job은 `stale(source_changed)`다. Source를 refresh(또는 다시 등록)하면 revision이 올라간다. PDF는 다시 parse하고, 이전 revision의 PDF 캐시는 참조가 풀려 지워진다.
- **파서 버전이 바뀜**(pypdf 업그레이드): 캐시 키가 달라져 다시 파싱한다. 이전 선택(selection)은 `stale`이다.
- **PDF 캐시 손상**: 읽을 때 SHA-256을 확인한다. 다르면 캐시를 지우고 `INDEX_NOT_READY(pdf_cache_corrupt)`를 낸다. 다시 parse하면 된다.
- **원본 보존**: 서비스는 사용자 파일을 쓰거나 지우지 않는다. 등록 해제도 서비스 데이터만 지운다.

## 5. 문제 복구

| 증상 | 확인 | 복구 |
| --- | --- | --- |
| 세션 생성 503 `PROTECTION_UNAVAILABLE` | `GET /api/v1/settings`의 protections | 서비스 연결·gate·transformer 확인. host 재시작 |
| run이 `TOKENIZER_UNAVAILABLE` | `.env`의 `SECURECODE_TOKEN_COUNTER`, llama 서버 상태(`curl http://127.0.0.1:8080/health`) | llama-server를 켜고 키를 맞춘다. `SECURECODE_LIVE_SMOKE=1 npm run test:live`로 계수 확인 |
| run 생성 503 `SERVICE_UNAVAILABLE` | context-service 상태(`/api/v1/health`가 degraded) | `npm run dev`로 다시 시작 |
| `SOURCE_CHANGED`, `stale_preview` | 파일이나 질문이 바뀜 | 다시 읽거나 미리보기를 다시 요청 |
| PDF job 404 | host 재시작 후 job 표 없음 | 다시 parse(캐시가 있으면 바로 ready) |
| 색인 `stale` | 파일이 바뀜 | `POST /workspaces/:id/index` |
| 디스크가 가득 참 | `runtime/`·`derived/` 크기 | 세션 닫기, 서비스 재시작(만료 정리), `derived/` 삭제 |
