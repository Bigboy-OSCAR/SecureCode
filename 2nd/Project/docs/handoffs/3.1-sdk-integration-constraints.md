# 3.1 SDK 검증 → 후속 작업 인계

> 발신 역할: 박준형 3.1 · 수신 역할: 박준형 3.2/3.5/3.6, 임우형 4.1/4.4/4.8
>
> 작성일: 2026-11-03 (Asia/Seoul) · 근거: [SDK_COMPATIBILITY.md](../architecture/SDK_COMPATIBILITY.md), [실행 증거](../../artifacts/verification/3.1/sdk-probe-result.json)

계약 schema 변경이 아니라, 설치된 `@cline/sdk@0.2.0`에서 실측한 **제약**을 넘긴다. 각 수신 작업이 자기 소유 파일에서 반영한다.

| ID | 수신 | 사실(실측) | 요구 |
| --- | --- | --- | --- |
| C-01 | 3.2 | SDK `.d.ts`는 `NodeNext`에서 457개 모듈이 미해결이라 타입이 `any`로 바뀐다. `Bundler`에서는 모두 해결된다 | host tsconfig `module: ESNext`, `moduleResolution: Bundler`, strict. 실행은 tsx/bundler. `@cline/*` 0.2.0 integrity 유지, Node 22/24 LTS 고정 후 `tools/sdk-probe` 재실행 |
| C-02 | 3.2/3.5 | SDK는 `CLINE_DIR`/`CLINE_DATA_DIR`에 세션·설정·global tool 설정을 쓴다. Windows에서는 dispose 뒤에도 같은 프로세스에서 폴더를 지울 수 없었다 | SDK import 전에 앱 전용 경로로 설정한다(`.securecode/` 아래, Git 제외). `localRuntime.configExtensions: []` |
| C-03 | 3.5 | 대기 중 `requestToolApproval`은 abort/stop으로 끝나지 않는다. 늦은 approved가 오면 abort 뒤에도 도구가 실행됐다 | 승인 broker: ID·sha256 입력 digest·만료, timeout/취소/세션 종료 때 거절, 늦은 결정 거부, `cancelSession` → `abort/stop` 순서 |
| C-04 | 3.5 | `toolPolicies`만으로는 provider `web_search`가 요청에 남는다. `enableTools:false`는 내장 도구와 `web_search`를 함께 없애고 `extraTools`는 유지한다 | 허용 도구는 프로젝트 wrapper(`extraTools`)와 명시 `toolPolicies`로만 구성한다. 세션 시작 시 첫 요청 tools 목록을 허용 목록과 대조 |
| C-05 | 3.5 | start/send는 중단·오류에도 resolve하고 `finishReason`으로 알린다. `interactive:false`면 첫 run 뒤 세션이 끝난다. status 이벤트는 `running/pending/idle/completed/cancelled` | run 상태는 `finishReason`과 Core status로 확정. 대화형 세션은 `interactive:true`. 이 값을 AppEvent로 매핑하고 Core 이벤트를 그대로 넘기지 않음 |
| C-06 | 3.5/3.6 | `agent_event.content_end`에 hook 이후 tool output이 실린다. 교체가 없으면 원문이 그대로 남는다 | AppEvent/SSE 변환에서도 크기 cap을 적용 |
| C-07 | 4.1/4.4 | Core message builder가 8,000자 초과 tool result를 provider 요청에서만 head/tail로 자른다. canonical history는 원문 전체를 유지한다. afterTool은 원문 전체를 받는다 | pointer 임계값 < 8,000자(그리고 ≤ 16 KiB). "SDK가 자른 결과"를 원본 저장이라고 표시하지 않는다 |
| C-08 | 4.4 | direct/object hook의 예외는 run을 실패시켜 원문을 막는다. hook timeout은 SDK가 강제하지 않는다(4.5초 대기) | pointer hook 내부 timeout + throw, `hookErrorMode:"throw"`. 필수 hook 미등록 시 세션 시작 차단 |
| C-09 | 4.8 | beforeModel view와 outbound body 크기가 다르다(709→598, 67,496→8,891 bytes). beforeModel `options.maxTokensPerTurn`은 outbound `max_tokens`를 바꾸지 않는다. fetch 경계 차단은 1회 시도로 끝나고 run은 `error`가 된다 | 최종 hard cap은 `ClineCoreOptions.fetch` wrapper. 출력 예약은 `config.maxTokensPerTurn`. 계수는 allowlist 필드로 만든 `count_tokens`(estimate) + margin. 불가 시 `TOKENIZER_UNAVAILABLE` |
| C-10 | 3.6/4.8 | live 키 없이 검증했다 | live `count_tokens`·실제 usage 대조·실 provider smoke는 3.6/4.8에서 수행 |
