# QASPER 선택 근거와 RAPTOR 논문과의 관계

**QASPER를 선택한다.** 연구 논문의 구조를 이용한 검색을 평가할 수 있고, 후보 세 자료 중 질문 수가 가장 적으며, 모든 질문에서 FULL을 실제 입력할 수 있다. 선정 근거는 자료 구조·규모·토큰 길이이고, 기존 실행의 답변이나 성능 점수를 비교해서 고른 것이 아니다.

## 1. RAPTOR에서 사용한 세 후보 비교

아래는 공식 원본을 준비한 자료의 질문별 통계다. 크기는 모델의 실제 토크나이저로 센 **본문 토큰**, FULL 적합성은 기존 고정 프롬프트·질문·ChatML 포장·출력 예약을 포함한 32,768토큰 한도 기준이다. 이것은 정답 품질 실험이 아니라 오프라인 입력 길이 점검이며 LLM 답변 호출은 없었다.

| 후보 | 고유 질문 | 정확히 같은 원문 문맥 | 본문 평균 / 중앙 / 최대 토큰 | FULL 입력 가능 |
|---|---:|---:|---:|---:|
| **QASPER** | **984** | **273** | **4,882 / 4,613 / 21,879** | **984개·100%** |
| QuALITY | 2,086 | 118 | 5,859 / 6,668 / 8,717 | 2,086개·100% |
| NarrativeQA | 3,425 | 115 | 79,476 / 51,819 / 484,288 | 565개·16.50% |

QASPER는 984개 전체 프롬프트를 오프라인으로 직접 토큰화했고, **최대 프롬프트 길이 + 출력 예약 128토큰 = 22,192토큰**이었다. 따라서 현재 조건을 유지하면 전체 984문항이 네 방식의 공통 비교 집합이다. QuALITY도 모두 들어가지만 질문 수가 약 두 배이며 선택지 본문 일치로 평가한다. NarrativeQA는 대부분 FULL을 실행할 수 없어, 한 자료만 고르는 이번 목표에서는 품질·비용의 전수 직접 비교보다 컨텍스트 초과 효과가 중심이 된다.

이 통계는 기존과 동일한 원본·전처리·프롬프트·토크나이저를 사용하는 선정 근거다. 새 준비 결과의 ID 집합·원문 해시·그래프와 최종 호출 길이는 새 실험에서도 검증해야 한다. 이전 일곱 자료의 미완료 결과를 이번 완료 결과와 섞지 않는다.

## 2. QASPER가 적합한 부분과 B의 결정적 한계

QASPER는 연구 논문에서 정보를 찾아 답하는 과제다. 짧은 사실 답변 외에 설명, yes/no, 답할 수 없음이 포함된다. 절 제목·문자 위치·원문 미리보기로 검색 목록을 만드는 문서용 색인과 자연스럽게 연결된다. 다만 현재 전처리에서 실제로 얻은 정보를 기준으로 설명해야 한다.

| 준비 결과 | 관측 수 | 해석 |
|---|---:|---|
| 절 제목이 인식된 논문 | 271 / 273 | 구조적 단서를 목록에 이용할 수 있다. |
| 인식한 절 제목 | 918 | 논문 전체 제목이 추출됐다는 뜻은 아니다. |
| 절 제목 라벨을 가진 조각 | 5,922 / 6,018 | 많은 조각이 위치·미리보기와 절 제목 정보를 갖는다. |
| 별도 문서 제목 필드가 채워진 root | 0 | ‘논문 제목까지 정교하게 색인했다’고 쓰지 않는다. |
| 분할된 같은 문단의 이어짐 연결 | 9,504 | 긴 문단의 이웃 조각을 더 읽게 하는 주된 연결이다. |
| 같은 논문 안의 절 제목 언급 연결 | 41 | 절 제목 언급을 통한 연결은 상대적으로 드물다. |
| 다른 문서로의 연결 | **0** | **B의 파일 간 확장 효과를 검증할 수 없다.** |

각 질문에는 한 논문만 제공된다. 이번 A와 B는 같은 논문 안에서 참조를 **1단계와 2단계** 따라가는 차이를 비교하며, 각각 독립적인 선택 호출을 수행한다. 대부분의 연결이 문단 이어짐이므로 B가 더 좋아져도 다른 파일의 import 관계를 잘 활용했기 때문이라고 설명할 수 없다. 다른 논문을 임의로 섞어 B에만 제공하면 공식 입력과 공정한 비교 조건이 달라진다. 파일 간 확장 검증은 별도의 다문서 또는 코드 과제가 필요하다.

## 3. RAPTOR에서 가져온 것과 재현하지 않는 것

[RAPTOR: Recursive Abstractive Processing for Tree-Organized Retrieval — ICLR 2024 최종 논문](https://proceedings.iclr.cc/paper_files/paper/2024/file/8a2acd174940dbca361a6398a4f9df91-Paper-Conference.pdf)은 **NarrativeQA·QASPER·QuALITY 세 데이터셋**을 사용했다. 이번에는 그중 QASPER라는 평가 과제를 선택했으며, RAPTOR 알고리즘을 실행한 것은 아니다.

| 구분 | RAPTOR 논문 | 이번 QASPER 실험 |
|---|---|---|
| 검색 자료 | 원문을 임베딩·군집화하고 재귀적으로 요약한 다층 트리 | 원문 조각·제목/문단 연결·단어 가중치 |
| 기본 조각 | 문장 경계를 고려한 약 100토큰 | 원문 보존, 조각 최대 256 모델 토큰 |
| 검색 | 임베딩 유사도, 여러 계층을 함께 검색하는 설정 | A/B는 목록 선택+연결 확장, R0는 TF-IDF 코사인 순위, FULL은 논문 본문 전부 |
| 검색 예산 | 일반 2,000토큰; UnifiedQA 실험은 400토큰 | A/B/R0의 답변 근거 최대 1,024토큰 |
| 모델 | 논문의 GPT 계열·UnifiedQA 등 | Qwen2.5-Coder-7B-Instruct Q5_K_M 로컬 모델 |
| 이번 주장 범위 | 논문 자체의 결과 | **RAPTOR가 사용한 데이터셋에서 수행한 별도의 네 방식 비교** |

논문의 SBERT 임베딩, UMAP/GMM 군집, GPT-3.5 요약 및 원 논문의 모델 설정을 재현하지 않는다. RAPTOR 공식 코드도 논문 표와 기본값이 완전히 같지 않다. 확인한 2024년 원저자 저장소 리비전은 `2e3e83e5c4aa6a9b5f2d8359f5b71a9159c20845`이며, [검색기 코드](https://github.com/parthsarthi03/raptor/blob/2e3e83e5c4aa6a9b5f2d8359f5b71a9159c20845/raptor/tree_retriever.py)의 기본 검색 예산은 3,500토큰이다. 따라서 데이터셋 이름이 같다는 이유로 논문 재현·RAPTOR 성능 검증·논문 점수와의 직접 우열 비교라고 표현하지 않는다.

## 4. 평가 원칙의 1차 근거

[SCROLLS — EMNLP 2022 논문](https://aclanthology.org/2022.emnlp-main.823/)과 [공식 평가 구현](https://huggingface.co/datasets/tau/scrolls/blob/927b875150ac8f02262ddd3b078d33a9debc935b/metrics/f1.py)을 근거로 공개 validation의 질문별 참조 답안을 묶고 최대 참조 F1을 계산한다. 정확한 원본 리비전과 해시는 [자료 출처 기록](research_sources.md)에 있다. RAPTOR 논문의 모든 평가 행을 SCROLLS의 이 validation ID 집합과 동일하다고 보장하는 목록은 확인되지 않았으므로, 그런 동일성은 주장하지 않는다.

TF-IDF는 새로 발명한 지표가 아니다. 단어 가중치와 벡터 비교의 배경은 [Salton·Buckley의 정보검색 연구](https://www.sciencedirect.com/science/article/pii/0306457388900210), 로그 빈도는 [정보검색 교재](https://nlp.stanford.edu/IR-book/html/htmledition/sublinear-tf-scaling-1.html)를 참고한다. 이번 R0의 평활 IDF·로그 TF·정규화·후보 묶음 및 예산 규칙은 동결한 구현을 기준으로 설명한다.

최종 보고서는 점수와 함께 총 입력 토큰, 한 호출의 최대 입력, 선택 호출 포함 비용, 측정 가능한 시간 및 실패를 제시한다. 한 번의 생성과 한 모델에서의 관측이며, 논문 원문을 공유하는 질문을 묶어 불확실성을 계산한다. QASPER 결과를 모든 코드 프로젝트·다문서 질문·다른 모델에 대한 보편적인 우열로 확대하지 않는다.
