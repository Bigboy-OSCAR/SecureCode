### 8.1 무엇을 고정하고 무엇을 바꿨나?

확인할 질문은 **“R0의 원문 검색 결과를 작은 색인으로 바꿔 한 번 더 고르면, 답변에 필요한 근거를 유지하면서 질문당 총 입력과 한 호출의 크기를 줄일 수 있는가?”**이다. H의 처리 과정은 [1.11절](#hybrid-method)에 설명했다. 한 번의 선택과 한 번의 답변으로 고정해 호출 비용과 누락 원인을 셀 수 있게 했다.

| 조건 | 이번 실행 |
|---|---|
| 평가 자료 | 기존 큰 파일 실험의 코드·질문·기준 답을 그대로 사용: 합성 Python 프로젝트 6개, 96문제(원래 48 + 추가 48) |
| 파일 크기 | 기존과 같은 약 4,099~4,157토큰, 533~553줄. 질문 대상 함수는 짧게 유지하고 무관한 보조 함수를 추가한 자료 |
| 새로 실행한 방식 | **B·R0·H** 각각 96문제 × 3회 = 총 **864개 답변**. 기존 답변을 복사해 재실행 결과로 세지 않음 |
| 별도 연습 실행 | 다른 프로젝트의 8문제를 세 방식으로 실행한 24개 답변. 통신·토큰 집계 확인에만 사용하고 평가 성적에 합치지 않음 |
| 모델·장비 | 기존과 같은 Qwen2.5-Coder-7B-Instruct Q5_K_M, M3 Pro·36GiB, 같은 모델·서버 지문. 컨텍스트 8,192, temperature 0, seed 1 |
| 원문과 출력 제한 | 세 방식의 답변용 원문 최대 1,024토큰, 선택 출력 최대 96토큰, 답변 출력 최대 128토큰. H의 목록 본문은 추가로 최대 512토큰 |
| 선택 범위 | B는 LLM이 출발 함수 하나를 고르면 프로그램이 함수 최대 8개와 참조 상수를 모음. H는 LLM이 목록 안에서 함수·상수 합계 최대 8개를 직접 지정함 |
| 실행 순서 | 같은 질문의 세 방식을 붙여 실행. 각 반복에서 가능한 6가지 순서를 각각 16번 배치. 모델의 프롬프트 캐시는 끔 |
| 실패 처리 | 형식·번호·개수 규칙을 어긴 선택이나 빈 선택은 최종값과 관계없이 오답. 출력 한도 도달도 오답으로 기록. 기준 답을 이용해 다시 고르거나 실패 질문만 재실행하지 않음 |
| 통계 비교 | H−R0와 H−B를 사전에 지정. 같은 프로젝트의 질문은 묶어서 계산하며, 두 정답률 비교에 Holm 보정 적용 |

**이번 실행의 B·R0와 비교하는 이유:** H는 검색과 선택 절차를 모두 바꾸므로 B와 비교하면 기존 선택 방식에서 무엇이 달라지는지, R0와 비교하면 원문 검색 뒤 선택 호출을 추가한 비용과 효과를 볼 수 있다. 기존 A·파일 전체·RF·RH·C는 앞선 실제 실행값을 참고한다. 이 다섯 방식까지 이번 세션에서 다시 실행한 것은 아니며, 특히 과거 시간과 새 시간의 차이를 H의 효과로 단정하지 않는다.

계획·코드·입력 파일을 본 평가 전에 고정하고, 이후 성적을 보고 설정을 바꾸지 않았다. 다만 **이미 여러 번 살펴본 동일 문제를 다시 사용한 탐색 실험**이다. 처음 보는 독립 평가 문제에서의 일반화나, 가능한 모든 결합 방식 중 최적의 설계를 입증하는 실험은 아니다.
