# UI 색인 생성 절 추가 검토

- 사용자·UI·백엔드·파서/검색 코드·LLM의 역할을 분리했다.
- 버튼 클릭부터 파일 확정, 파싱, 참조 연결, 요약, 저장/검색 준비, 사용 가능한 버전 반영까지 설명했다.
- A/B/R0의 준비에는 요약 LLM 호출이 없고, RF/RH/C의 준비에는 필요한 요약 호출이 있음을 명시했다.
- C는 RH 자료를 공유하며 질문별로 선택된 자료를 정리한다.
- JSON 저장 자료와 실행 시 메모리에 준비하는 TF-IDF를 구분했다.
- 실제 실험 코드와 아직 구현하지 않은 UI 연동·진행 표시·버전 교체·갱신 정책을 구분했다.
- 독립적인 코드 대조 검토에서 필수 수정사항은 없었다. 사용자 대상 UI 사용성 시험은 수행하지 않았다.
- 기존 문서는 신규 절/목차와 번호 변경을 되돌리면 바이트 단위로 동일하다. 기존 수치 194개와 로컬 링크 48개를 점검했다.
