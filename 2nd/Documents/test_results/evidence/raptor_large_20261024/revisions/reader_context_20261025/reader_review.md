# 03번 보고서: 독자 관점의 설명 점검

검토일: 2026년 10월 25일. 검토 대상은 같은 폴더에 보관한 수정 전 보고서와 `report_after.md`다. 새 벤치마크를 실행하거나 실제 독자에게 이해도 시험을 실시하지 않았다.

## 검토 기준과 발견

처음 읽는 사람이 실험의 목적, 비교 기준, 처리 과정, 기대 효과, 실제 성과와 한계를 문서 안에서 연결할 수 있는지 살폈다. 별도의 두 검토 관점(입문 독자의 맥락, 정량 비교의 범위)을 적용한 뒤 보완된 문장을 재검토했다.

**수정 전 판단:** 개별 방식의 코드·색인 예시는 구체적이고 결과 수치와 한계도 대부분 존재했다. 그러나 독자가 그것을 읽어야 하는 이유와 파일 전체 대비 이득을 스스로 조합해야 했다. 없는 설명과 너무 늦게 나오는 설명이 함께 있었다.

| 맥락 공백 | 독자가 할 수 있는 오해 | 보완 위치와 내용 |
|---|---|---|
| 토큰·컨텍스트와 자료 선택의 목적이 설명되기 전에 수치·AST가 등장 | 색인이 무엇을 줄이는지, 왜 준비하는지 알기 어려움 | 도입에서 길이 단위와 한 호출의 입력·출력 한도를 정의. 1.1절에서 질문 전 준비 → 질문 후 선택 → 동일 모델에 자료 전달 과정을 연결 |
| ‘파일 전체’의 기준 설명이 1.9절에 등장 | 프로젝트 전체나 필요한 모든 파일을 넣은 조건이라고 생각할 수 있음 | 도입에서 대상 함수가 있는 파일 하나와 경로 제공 조건을 명시. 1.2절에서 service.py 전체에도 rules.py의 계산식과 policy.py의 값은 빠짐을 설명 |
| 요약 생성 구조는 설명하지만 시도한 이유가 약함 | 비용만 추가한 방법으로 읽히거나, 요약을 만들면 자동으로 정확해진다고 생각할 수 있음 | 1.1절에서 각 비교 목적을 제시. 1.6절에서 기능 설명·관계 파악이라는 기대와 단어 검색·정확한 세부값을 요구하는 평가의 제약을 연결 |
| 정확도·누적 입력·호출별 입력·준비 비용의 의미가 분산 | A의 342.0토큰을 모든 호출의 평균이나 최댓값으로 읽거나, 토큰 절감을 정확도 개선과 동일시할 수 있음 | 도입에서 파일 하나 전체 대비 결과와 대가를 함께 제시. 4.1절에서 평균 누적 입력 500.9와 질문별 큰 호출 입력의 평균 342.0을 구분. 금전 요금은 미측정임을 명시 |
| ‘정답률’의 대상이 결과 뒤에 정의됨 | 검색 적중률이나 보안 취약점 탐지 성능으로 오해할 수 있음 | 도입에서 최종 코드 동작 답변을 JSON 값으로 채점한다고 설명. 6개 합성 프로젝트·96문제·한 모델이라는 평가 범위를 명시 |

## 보완 후 독자가 답할 수 있어야 할 질문

| 독자의 질문 | 문서가 전달해야 할 답 | 위치 |
|---|---|---|
| 무엇을 개선하려는가? | 코드 질문에 필요한 자료를 골라 컨텍스트 사용을 줄이되 정확도를 유지하거나 높일 수 있는지 비교한다. | 도입·1.1 |
| 색인을 LLM에 통째로 보내는가? | 색인은 자료를 찾는 준비 자료다. 최종 답변에는 선택된 원문·요약이 들어간다. A·B는 후보에서 출발 함수를 고르는 호출도 있다. | 1.1·1.3~1.9 |
| 파일 전체보다 적게 보내면서 근거가 더 완전할 수 있는가? | 파일 하나에는 외부 정의가 없다. B·R0 등은 여러 파일에서 필요한 부분을 모을 수 있다. 실제 정확도 개선은 별도로 확인해야 한다. | 도입·1.2·1.4~1.5 |
| 요약은 왜 추가했는가? | 코드의 기능 설명과 상위 관계를 검색에 활용하려는 기대 때문이다. 이번 RF·RH·C가 R0보다 더 많은 정답을 내지는 못했다. | 1.1·1.6·3.1 |
| 무엇이 얼마나 나았는가? | 큰 파일에서 A의 누적 입력은 파일 하나 전체보다 88.3% 작았다. R0는 입력을 72.7% 줄이고 25/96개를 맞혔다. C는 RH보다 총 입력 18.2%를 줄였다. 각각의 비교 기준과 대가가 다르다. | 도입·3·4·6 |
| 항상 선택 방식이 더 나은가? | 작은 파일에서는 추가 호출·넓은 수집 범위 때문에 누적 입력이 늘었다. 최고 정답률도 낮고 합성 자료·모델·통계 설계의 한계가 있다. | 도입·3.2~3.3·6·부록 A |

## 재검토 판단과 보존 범위

편집 검토에서는 위 다섯 가지 핵심 공백이 해소되었다고 판단했다. 재검토 과정에서 RF↔RH 비교를 별도 ‘구조 이해 능력 시험’처럼 읽지 않도록 문구를 좁혔고, 500.9토큰이 질문당 누적 입력의 평균임을 명시했다.

기존 실험 수치·표·코드 예시·실제 답변·통계와 한계는 보존한다. 추가한 문맥은 측정하지 않은 효용을 관측 성과로 주장하지 않는다. 반복 실행 수를 독립 문제 수로 늘려 세지 않으며, 기존 정답률이나 채점 기준을 변경하지 않는다.

이 판단은 문서의 설명 구조에 대한 검토다. 독자의 실제 이해도나 읽는 시간은 측정하지 않았으므로, 모든 독자가 이해할 것이라고 보장하는 결과는 아니다.
