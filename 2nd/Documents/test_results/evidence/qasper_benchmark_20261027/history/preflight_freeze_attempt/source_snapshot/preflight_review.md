# QASPER 단일 데이터셋 실험 사전 점검

사용자의 범위 정정에 따라 QASPER 공개 검증 세트만 새로 실행한다. 이전 7종 실험의 결과는 재사용하지 않는다. 이 문서는 실험 준비 검증이며 답변 품질의 결과가 아니다.

## 자료와 비교 조건

- SCROLLS 고정 revision의 QASPER validation: 원본 정답 행 1,726개, 고유 질문 984개, 본문 문맥 273개. 모든 정답 참조를 유지한다.
- A·B·R0·FULL을 질문마다 한 번씩 실행한다: 결과 3,936행, 평가 모델 호출 5,904회. A/B는 선택과 답변 두 호출, R0/FULL은 답변 한 호출이다. 전송 점검 1회는 평가에서 제외한다.
- 원문 본문으로만 문서 조각과 연결을 만든다. 질문과 정답은 색인 제작에 사용하지 않는다. 질문은 검색 또는 선택 시점에만 사용한다.
- QASPER는 단일 논문 입력이므로 파일 간 참조가 없다. A/B 차이는 논문 내부 연결을 따라가는 깊이(1/2)이다. 코드의 import 확장 성능을 검증한 실험이 아니다.
- A/B/R0의 본문 예산은 1,024토큰. A/B 목록 예산은 별도 2,048토큰. 모델 한도는 32,768토큰, 답변 상한은 128토큰이며 FULL은 원문을 자르지 않는다.
- A/B의 선택 호출 비용까지 총 입력에 포함하고 한 호출의 최대 입력도 따로 집계한다. 질의 시간은 자료 로딩 및 TF-IDF 제작과 분리한다.
- 점수는 공식 SCROLLS 방식의 정답 참조별 최대 token F1이다. 정확도와 혼동하지 않는다. 같은 문서를 묶은 paired cluster bootstrap 10,000회로 차이의 구간을 구한다.

## 확인한 증거

- 준비 자료 독립 전수 검증 PASS: 질문 ID 집합·정답 참조·원문 재구성·문자 구간·256토큰 상한·실제 원문 미리보기·모든 연결의 생성 근거를 검사했다. `prepared_verification.json` 참조.
- 준비/실행/지표/후처리 기본 검사 34개 통과. 분석/최종 증거 검증/보고서 검사는 담당 모듈에서 별도로 수행한다.
- GGUF 토크나이저와 서버의 세 입력 토큰 계산이 일치했다. 실제 전송 점검 한 번은 `2`를 반환했다. 이 점검은 평가 점수·비용에 포함하지 않는다.
- 실행기는 요청 의도를 먼저 저장하고 응답 원본을 보존한다. 미해결 요청은 자동 재시도하지 않는다. 배타 잠금과 완료 마커로 중복 실행 및 불완전 결과 보고를 막는다.
- 이전 실험의 Python 가상환경은 공유하되 새 위치의 지표/소스와 설치 버전을 다시 기록했다. 모든 실험 소스·자료·모델·추론 바이너리 해시는 본 평가 직전에 동결한다.

## 해석 범위

RAPTOR가 사용한 데이터셋을 활용한 A/B/R0/FULL 비교이다. RAPTOR의 군집·요약 알고리즘 또는 논문 점수를 재현한 실험이 아니다. 단일 모델·단일 예산·한 번의 결정적 생성으로 얻는 결과이며 예산별 최적성이나 코드 프로젝트 전반의 우위를 입증하지 않는다. 이전 소규모 코드 실험과 수치를 합산하지 않는다.
