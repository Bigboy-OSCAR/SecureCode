# 문서 벤치마크 독립 사전 점검

점검일: 2026-10-27. 대상: SCROLLS 검증 4종과 LongBench v1 테스트 3종의 A·B·R0·FULL 비교. 이 문서는 **실행 안전성·입력 범위 점검**이며, 아직 정답 품질이나 우열을 판정한 결과가 아니다.

## 1. 갱신된 실행기 판정

이전에 지적했던 실행기 문제의 수정 사항을 실제 코드에서 재확인했다. 아래 8개 기존 단위검사와 4개 독립 추가 검사도 모델 호출 없이 통과했다. 이번 점검에서 실행기 자체의 새로운 중대한 결함은 발견하지 못했다. 다만 데이터 준비가 끝난 후 3절의 전수 일치 검사를 통과한 상태에서 실험 조건을 동결해야 한다.

| 항목 | 확인한 동작 | 확인 방법 |
|---|---|---|
| 선택기 출력 | 공백 제거 후 `n`+숫자 6자리 **하나 전체**와 일치해야 하며 목록에 있어야 한다. `stopped_limit`과 `stop_type=limit` 모두 실패 처리한다. | 코드 및 기존 검사 통과 |
| 호출 전 기록 | 실제 요청 전에 `pending` 기록을 저장한다. 전송 오류는 오류와 비용 불확실성을 남긴다. 미해결 기록이 있으면 자동 재요청하지 않는다. | 코드 및 고의 전송 오류 검사 통과 |
| 응답 보존 | 응답을 먼저 `received`로 저장하고, 입력 잘림·토큰 불일치를 검증한다. 실패해도 원래 응답이 남고 자동 재요청이 막힌다. | 입력 잘림/토큰 불일치 각각 독립 검사 통과 |
| 재시작 | 완료된 호출은 요청 내용이 같을 때만 재사용한다. 연속 번호의 원자적 결과 파일이 진실의 원본이며 JSONL은 이 파일들로 다시 만든다. | 코드, 요청 동일성 검사, 결과 번호 누락 거부 검사 통과 |
| 변경 탐지 | 실행 시 데이터 목록·작업 목록·순서·소스·모델·추론 바이너리를 검증한다. 문서 로딩 시 파일 SHA256 및 원문 해시를 검증한다. | 실제 코드 확인; 실제 파일 변조 실험은 수행하지 않음 |
| 중복 실행 | CLI 실행은 배타적 파일 잠금을 얻어야 한다. | 실제 코드 확인; 동시 프로세스 충돌 실험은 수행하지 않음 |
| 원문 및 예산 | 문서 조각은 원문 오프셋의 문자열을 유지한다. 예산을 넘는 조각은 통째로 제외한다. FULL은 원문을 자르지 않고 초과를 기록한다. | 기존 검사 통과 |
| 순서 | 모든 질문에 4개 방식이 정확히 한 번씩 배정된다. 고정 시드의 순서가 재현된다. | 독립 합성 자료 49문항·196배정 검사 통과 |

기존 `test_run_experiment.py` 8개 검사가 모두 통과했다. 독립 추가 검사는 잘린 응답 보존, 토큰 수 불일치 응답 보존, 결과 번호 누락 거부, 네 방식 전수 배정·순서 재현성의 4개이며 모두 통과했다. 임시 폴더만 사용했고 실제 모델 추론이나 실험 결과 기록을 추가하지 않았다.

현재 저장된 `smoke_transport.json`에서는 토크나이저 대조 3건이 기록되어 있고, 짧은 실제 요청의 입력 26토큰과 서버 `tokens_evaluated=26`이 일치한다. 이는 짧은 전송 경로의 증거이다. 문서 전체 실험 완료나 모든 길이에서의 검증을 뜻하지 않는다.

## 2. 원본 파일 독립 전수 집계

준비된 자료나 목록에 의존하지 않고 `raw/*.jsonl`을 한 줄씩 읽어 직접 집계했다. SCROLLS의 `id`는 질문 식별자로, 같은 질문의 여러 정답 행을 하나의 질문으로 묶었다. LongBench는 `_id`를 사용했다.

| 자료 | 원본 행 | 고유 질문 | 중복 질문의 입력 불일치 | 문맥 수에 대한 독립 확인 |
|---|---:|---:|---:|---|
| QMSum | 272 | 272 | 0 | 첫 빈 줄 뒤 문맥 35개 |
| Qasper | 1,726 | 984 | 0 | 첫 빈 줄 뒤 문맥 273개 |
| NarrativeQA | 5,878 | 3,425 | 0 | 첫 빈 줄 뒤 문맥 115개 |
| QuALITY | 2,086 | 2,086 | 0 | 선택지 전체를 분리한 뒤 별도 집계 필요 |
| HotpotQA | 200 | 200 | 0 | `context` 값 200개 |
| MuSiQue | 200 | 200 | 0 | `context` 값 200개 |
| MultiFieldQA-en | 150 | 150 | 0 | `context` 값 112개 |
| **합계** | **10,512** | **7,317** | **0** | 문맥 수를 질문 수와 혼동하지 않는다. |

따라서 네 방식의 예정 결과 수는 **7,317 × 4 = 29,268행**이다. A/B에는 별도 선택기 호출이 있으므로 이 수가 실제 LLM 호출 수와 같지는 않다. FULL의 컨텍스트 초과도 결과 행에는 포함하지만 실제 호출은 발생하지 않는다.

**NarrativeQA 추가 확인:** 파일 크기 1,961,877,179바이트. 5,878행 모두 첫 빈 줄 앞은 줄바꿈 없는 질문 한 줄이며 `?`로 끝난다. 구분자 누락·빈 질문·빈 문맥·빈 정답이 0건이다. 같은 `id`의 입력은 모두 동일하다. 질문당 정답 행 개수는 1개 1,002문항, 2개 2,403문항, 3개 12문항, 4개 7문항, 6개 1문항이다. 따라서 무조건 정답 두 개로 가정하거나 행별로 반복 평가하면 안 된다.

**QuALITY 추가 확인:** 모든 2,086행의 필드는 `id`, `pid`, `input`, `output`뿐이다. `is_hard` 등 난도 표시는 없다. 이 파일만으로 hard 부분집합 점수를 만들 수 없다. 첫 빈 줄은 질문과 선택지 사이에 있고, 그 뒤에 선택지와 원문 기사가 이어진다. 첫 빈 줄 뒤를 곧바로 원문으로 삼으면 선택지를 문서 색인에 섞게 된다. 질문+선택지와 원문 기사를 올바르게 분리해야 한다.

7개 파일 모두 마지막 줄바꿈이 있고, 확인한 질문·문맥·정답은 비어 있지 않았다. 문맥 수는 위에 명시한 구분 규칙에 대한 문자열 해시 집계이며, 문서 내부의 제목별 하위 문서 수나 검색 조각 수를 뜻하지 않는다.

## 3. 동결 직전 확인할 데이터 조건

원본 집계는 완료했지만 이 문서를 작성한 시점에는 준비 담당의 최종 `tasks.jsonl`과 `data_manifest.json`이 아직 없었다. 따라서 아래 항목은 **미검증**이다. 준비 코드의 자동 검증 및 최종 산출물을 통해 확인한 뒤 동결한다.

1. 자료별 고유 질문 ID 집합이 원본과 준비된 작업 목록에서 정확히 같고, 누락·추가·중복이 없다. 단순히 7개 자료가 있다는 검사만으로 전수 사용이 증명되지는 않는다.
2. 각 질문의 모든 정답 참조를 보존한다. 추론용 질문/문서/색인 제작에 정답 필드를 넘기지 않는다.
3. QuALITY의 선택지는 질문에 포함하고 기사에서는 제외한다. 나머지 자료의 질문/문맥 분리도 원본과 일치한다. FULL은 준비 단계부터 원문 문자를 자르거나 공백 정규화하지 않는다.
4. 모든 검색 조각의 오프셋이 원문 안에 있고, 원문을 그대로 가리키며, 조각 토큰 상한과 참조 대상 유효성·참조 생성 규칙을 만족한다. 자료별 하위 문서·연결 수를 기록한다.
5. 완성된 작업 목록에서 모든 질문에 A/B/R0/FULL이 한 번씩 있는 29,268개 배정을 확인한다. 실제 모델 32,768 컨텍스트 설정, 모델 경로 및 토큰 수가 검사와 일치해야 한다.
6. 공식 지표 구현의 단위검사와 다중 정답 처리 검사가 끝나야 한다. ROUGE 및 문장 분리 자원의 실제 설치 버전을 남긴다.

## 4. 결과 해석에서 유지할 조건

- 이번 비교는 **32,768토큰 컨텍스트**에서 네 방식에 동일하게 시행하는 새 실험이다. 기존 8,192 설정 결과와 토큰·속도·우열을 직접 합쳐 평균내지 않는다. 모델·환경·출력 상한·자료·지표를 함께 표시한다.
- A/B/R0는 본문 근거 1,024토큰 예산을 공유한다. A/B의 목록·선택 호출 비용까지 합산한 총 입력과 한 호출의 최대 입력을 따로 보고해야 한다. 색인/TF-IDF 준비 비용은 질의 시간과 분리되어 기록된다.
- FULL이 용량을 넘으면 호출하지 않는다. 그 0토큰·0호출을 근거로 FULL이 더 저렴하다고 결론 내리지 않는다. 전수 완료율, 실패를 포함한 운영 결과, **FULL도 들어가는 동일 질문 부분집합**의 품질·비용을 함께 제시한다.
- A/B는 문서의 제목·구간·미리보기·명시적 참조를 이용한 문서용 변형이다. 코드 AST 색인 자체를 실행한 결과나 RAPTOR 재현 결과라고 쓰지 않는다. 단일 문서 자료에서 A/B 차이는 주로 참조 깊이이며, 여러 파일 확장 효과와 구별한다.
- RAPTOR 논문이 사용한 자료는 NarrativeQA·QASPER·QuALITY 세 가지다. 여기의 7종 전체와 동일한 실험을 논문이 수행했다고 설명하면 안 된다. 1,024토큰 예산·로컬 모델·문서용 A/B·일부 지표는 본 실험의 선택이다. 근거는 `research_papers.md`에 정리했다.
- 한 번의 결정적 생성은 질문 집합의 성능 차이를 측정한다. 생성 반복의 변동성이나 보편적인 우위를 입증하지 않는다. 자료별로 점수·완료율·실패율·토큰·시간과 짝지은 차이를 함께 보고한다.
