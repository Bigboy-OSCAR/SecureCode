파일 하나 전체 입력 대비 토큰 사용량 재현

이 추가 분석은 새로운 LLM 답변을 생성하지 않는다.
A/B/R0의 원래 864개 평가 기록과 고정된 96문제·프로젝트 원문을 사용한다.
모델 서버를 켜지 않고 원래 모델의 llama-tokenize로 입력 길이만 계산한다.

비교 기준
- 질문의 target_uri가 가리키는 함수가 정의된 파일 하나 전체.
- import, 주석, 마지막 줄바꿈 포함. 추가 제목 없이 원문 그대로 사용하며 자르지 않는다.
- 파일을 이미 안다고 가정해 함수 선택 호출 없이 같은 질문/답변 지시문/대화 형식으로 입력한다.
- A/B/R0의 실제 전달 자료에는 원래 제목, 코드 표시, 중복이 포함된다.
- 파일 전체 방식의 정확도, 응답 시간, 생성 출력 토큰은 측정하지 않았다.
- 전체 파일 기준의 추가 입력은 실제 추론 요청 없이 완성된 입력 문장의 토큰을 직접 센 값이다.
- 총 입력량은 호출 간 합계, 컨텍스트 점유는 질문별 가장 큰 한 호출의 입력량으로 구분한다.

프로젝트 루트 /Users/oscar/Desktop/SecureCode 에서 실행한다.
이미 끝난 자료를 덮어쓰지 않도록 존재하지 않는 출력 경로를 지정한다.

FILE_TOKEN_REPRO_OUT=/Users/oscar/Desktop/SecureCode/2nd/Documents/test_results/evidence/file_tokens_reproduction_new
python3 2nd/experiments/symbol_raptor/analyze_file_tokens.py --out "$FILE_TOKEN_REPRO_OUT"

summary.json의 status가 PASS인지 확인한다.
원래 기록의 토큰 수 864개, 세 반복의 입력량 일치, 동일 모델·토크나이저,
질문별 정수 토큰 합계를 사용한 평균/비율 재계산을 확인한다.
파일별 원문 해시는 summary.json의 files에, 입력 해시는 protocol.json에 있다.
token_counts.json에는 계산한 문자열과 길이, 토크나이저 실행 정보가 들어 있다.

현재 검증된 추가 분석을 포함해 지정된 Markdown 보고서를 재생성하려면:

python3 2nd/experiments/symbol_raptor/report_r0.py --token-analysis 2nd/Documents/test_results/evidence/file_tokens_20261024

--token-analysis를 생략하면 원래 A/B/R0 보고서만 생성되므로, 이번 추가 내용을 유지하려면 반드시 지정한다.
새 출력 경로에서 재계산한 결과를 사용하는 경우 --token-analysis에 그 경로를 지정한다.
보고서 하단 계산 근거 링크는 지정한 분석 폴더를 가리킨다. 다른 경로로 재현할 때는 이 안내 파일도 함께 복사한다.
